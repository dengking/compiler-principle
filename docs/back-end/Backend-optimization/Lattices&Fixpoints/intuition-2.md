# 编译器优化中的 Lattice 与 Fixed Point：一篇建立直觉的整合讲解

> 本文中同时保留两种互为镜像的写法：
> - **写法 A**：join、自下而上，求**最小**不动点。抽象解释文献和 Møller & Schwartzbach《Static Program Analysis》等教材采用这种写法。
> - **写法 B**：meet、自上而下，求**最大**不动点。龙书采用这种写法。
>
> 两种写法描述的是同一件事，只是把同一张图倒过来画。读者可以对照着读，遇到任何一本教材都不会再被方向搞糊涂。

---

## 零、先统一语言：用“角色”代替 ⊤ 和 ⊥

初学者最常见的困惑是：**⊤ 和 ⊥ 在不同教材里含义正好相反。** 为了不被符号牵着走，本文先给格里的两个端点起两个与方向无关的“角色名”：

| 角色             | 含义                          | 侦探比喻        |
| -------------- | --------------------------- | ----------- |
| **UNDEF（起点端）** | 尚无信息。还没有任何执行路径把信息带到这里       | 还没有任何证人到场   |
| **NAC（保守端）**   | Not A Constant，不是常量。已经放弃精确性 | 证词互相冲突，只能放弃 |

两种写法只是把这两个角色放在图的不同位置：

| | 写法 A（join / 自下而上） | 写法 B（meet / 自上而下） |
|---|---|---|
| UNDEF（起点） | **⊥**（底） | **⊤**（顶） |
| NAC（保守端） | **⊤**（顶） | **⊥**（底） |
| 合并操作 | join ⊔ | meet ⊓ |
| 迭代中值的移动方向 | 往上 | 往下 |
| 求得的结果 | 最小不动点（LFP） | 最大不动点（MFP） |
| 比喻 | 信息水位**上涨** | 沿楼梯**下楼** |

**记住一句话就够了：无论图怎么画，迭代总是从 UNDEF 出发，朝 NAC 的方向移动。**

## 一、动机：为什么需要这套东西？

编译器想在**不运行程序**的情况下回答这样的问题：

- 这一行的 `x` 是不是一定等于常量 3？（常量传播）
- 这个变量之后还会被用到吗？（活跃变量分析）

真正的难点是**循环**。循环头的信息依赖循环体末尾，循环体末尾的信息又依赖循环头，信息依赖在控制流图（CFG）上形成了一个**环**，没办法从头到尾一遍算完。

> 注意：这和用户的代码是否死循环**无关**。静态分析不执行代码，哪怕程序里有 `while(1)`，分析器也不会因此卡住。只要 CFG 中有环，就需要迭代求解。

于是做法只能是：**先给每个程序点一个初始答案，绕着环反复修正，直到所有答案都不再变化。**

- **Lattice** 规定答案的形状，以及两个答案汇合时怎么合并。
- **Fixed point** 就是所有答案都不再变化的那个状态。

## 二、Lattice：知识精确度的层级地图

### 1. 常量传播的格

对于“变量 x 的值是什么”，编译器能给出的结论只有三类：尚无信息、一定是某个常数 c、不是常量。

**写法 A（join，UNDEF 在底）：**

```
                 ⊤  = NAC（不是常量）
          /   /   |   \   \
   ...  -1   0    1    2   3  ...   （一定是某个常数）
          \   \   |   /   /
                 ⊥  = UNDEF（尚无信息）
```

**写法 B（meet，UNDEF 在顶）：**

```
                 ⊤  = UNDEF（尚无信息）
          /   /   |   \   \
   ...  -1   0    1    2   3  ...   （一定是某个常数）
          \   \   |   /   /
                 ⊥  = NAC（不是常量）
```

两张图上下翻转，内容完全一样。

几点说明：

- **格不是树。** 每个常数同时连着上下两端，Hasse 图里有很多条“菱形”路径。我们关心的是它的**高度**：从 UNDEF 到 NAC 最长只有 2 步。
- **UNDEF 不是“可能是任何值”。** “运行时可能是任何值”说的恰恰是 NAC。UNDEF 的意思是“还没有信息到达这里”，它在合并时不施加任何约束。
- **NAC 永远是安全的。** “我不知道它是不是常量”这句话不会出错，但也帮不上忙。分析的目标是**在安全的前提下尽可能精确**。

### 2. 合并规则：证人对证词

当 `if-else` 两个分支汇合，或者循环头同时接收“第一次进入”和“绕回来”两条边时，需要合并信息。合并规则用角色名写出来，两种写法通用：

| 证人 A | 证人 B | 合并结论 | 直觉 |
|---|---|---|---|
| UNDEF | v | v | 一个证人没来，只听另一个 |
| c | c | c | 证词一致 |
| c | d（c ≠ d） | NAC | 证词冲突，只能放弃 |
| NAC | 任意 | NAC | 有人已经说“不确定”了 |

写法 A 称这个操作为 join：在图上找两个结论**上方**最近的公共点。写法 B 称之为 meet：在图上找两个结论**下方**最近的公共点。由于图是翻转的，两者找到的是同一个结论：**既不撒谎，又尽可能精确的共同结论。**

### 3. 另一类常见的格：集合

活跃变量、到达定值、可用表达式等分析使用“集合”格。以变量 {a, b, c} 为例，它的 Hasse 图分为四层：

- 第 0 层：{ }
- 第 1 层：{a}、{b}、{c}
- 第 2 层：{a,b}、{a,c}、{b,c}
- 第 3 层：{a,b,c}

相邻两层之间，**一个集合与它多一个元素的超集相连**。例如 {a,b} 向下连接 {a} 和 {b}，向上连接 {a,b,c}。这个格的高度等于元素个数（这里是 3）。

集合格上也存在镜像，而且分析的性质决定了哪一端是“保守端”：

| | may 分析（如活跃变量） | must 分析（如可用表达式） |
|---|---|---|
| 含义 | 只要**某条**路径上成立就算 | **所有**路径上都成立才算 |
| 合并 | 并集 ∪ | 交集 ∩ |
| 起点（UNDEF 角色） | 空集 ∅ | 全集 U（程序入口除外，入口单独规定为 ∅） |
| 保守端（安全端） | 大集合（宁可多报） | 小集合（宁可少报） |

由此可见，**“⊤ 永远安全”这种说法依赖于约定**。真正不变的规律是：**保守端是安全的，起点端是乐观的。**

## 三、Transfer Function 与单调性

### 1. 每条语句都是一个“传话筒”

把每条语句想象成一个传话的人：拿到上游的笔记，按自己的规则改写，再传给下游。这个改写规则就是 **transfer function**。

| 语句           | 对 x 的作用                                                       |
| ------------ | ------------------------------------------------------------- |
| `y = x + 1`  | 若 x 是 UNDEF，则 y 为 UNDEF；若 x 是 c，则 y 为 c+1；若 x 是 NAC，则 y 为 NAC |
| `x = 2`      | **无论输入是什么，输出都是 x = 2**（赋值会覆盖旧笔记）                              |
| `x = read()` | 无论输入是什么，输出都是 x = NAC                                          |

第二行很关键：**赋值语句会把信息重置。** 上游传来的 NAC，到了 `x = 2` 之后就变成了 2。前两篇讲解中的错误，都源于忽略了这一点。

### 2. 单调性的准确含义

**单调性是 transfer function 的性质：输入越靠近保守端，输出不会反而更远离保守端。**

- 写法 A：若 a ⊑ b，则 f(a) ⊑ f(b)。输入越高，输出不会越低。
- 写法 B：同一个式子，图倒过来读。输入越低，输出不会越高。

上表三条语句都满足单调性。

### 3. 单调性本身并不保证“只往一个方向走”

这是最容易混淆的地方。“迭代中每个程序点的值只朝 NAC 方向移动”需要**两个条件**：

1. transfer function 和合并操作都是单调的；
2. **从 UNDEF 端出发。**

推理过程如下。用写法 A 表示：设整个程序的更新为 F，起点为 ⊥。

- ⊥ 是最低点，所以必然有 ⊥ ⊑ F(⊥)。
- 两边同时施加单调的 F，得到 F(⊥) ⊑ F²(⊥)。
- 依此类推，得到 ⊥ ⊑ F(⊥) ⊑ F²(⊥) ⊑ …，整条链单调上升。

写法 B 完全对称：⊤ ⊒ F(⊤) ⊒ F²(⊤) ⊒ …，整条链单调下降。

如果**不**从起点端出发，值是可以“往回走”的。第五节会给出一个具体例子。

### 4. “不回头”说的是哪个维度？

要区分两个维度：

- **同一个程序点，在不同迭代轮次之间**：值只朝 NAC 方向移动，不会回头。
- **沿着代码往下走，经过不同程序点**：值可以随意变化。上一行 x 还是 NAC，经过 `x = 5` 之后就变成了 5。

所以，“一旦是 NAC 就永远变不回常量”这句话**只对同一个程序点的迭代过程成立**，并不是说“后面的代码再也变不回常量”。

## 四、为什么一定会停？

### 1. 直觉版本

| 写法 A | 写法 B |
|---|---|
| 水位只涨不落，水池有顶 | 只下楼不上楼，楼梯有底 |

> **只朝一个方向移动 + 路程有限 = 一定会停**

### 2. 补充几个细节

- **一次可能跨多级。** `x = read()` 会让 x 从 UNDEF 直接跳到 NAC，跨过了常量层。终止性只要求“每次变化都是严格移动”，并不要求“每次只走一步”。
- **要考虑整个程序的状态。** 整个程序的状态是“所有程序点 × 所有变量”构成的**乘积格**，它的高度是各分量高度之和。在常量传播中，这个高度不超过 2 × 程序点数 × 变量数。只要发生变化，就至少有一个分量移动了至少一级，所以变化的总次数有上限。无论循环嵌套多少层，分析都会终止，只是代价会随规模增长。
- **高度无限怎么办？** 区间分析的格，比如 [0,0] ⊑ [0,1] ⊑ [0,2] ⊑ …，可以无限延伸。此时需要 **widening** 操作，主动“跳一大步”来强制终止。
- **终止 ≠ 正确。** 有限高度加单调性只保证**终止**。结果是否**安全（sound）**，取决于 transfer function 和合并操作是否正确地刻画了程序语义，这是另一个问题。

## 五、Fixed Point：自洽的答案

### 1. 含义

不动点就是满足 **F(S) = S** 的状态 S：把当前所有程序点的结论代入方程再算一遍，得到的还是它们自己。

**数独的比喻最贴切**：反复用规则填格子，只填不擦，格子总数有限。直到扫完一整轮都没有新格子能填，此时所有已知信息互相自洽。

> 关于“不停按计算器 cos 键”的比喻：它能很好地说明 f(x) = x 的含义（在弧度模式下会停在 0.739…），但它的机制是**无限逼近一个极限**，只是因为显示精度有限才“看起来停了”。数据流分析则是在有限格上**有限步内精确到达**不动点。因此这个比喻不适合用来解释“为什么会停”。

### 2. 例一：标准迭代过程

```c
x = 1;
while (c) {
    y = x + 1;
    x = 2;
}
```

各程序点如下：

```
        x = 1                ← P0：x = 1
          │
          ▼
   ┌──► [H 循环头] ──(c 为假)──► 出口
   │      │ (c 为真)
   │      ▼
   │    y = x + 1            ← P1（这条语句之后）
   │      │
   │    x = 2                ← P2（这条语句之后，即循环体末尾）
   └──────┘
```

循环头的值由两条入边合并而来：**H.x = 合并(P0.x, P2.x)**。迭代顺序为每轮依次计算 H、P1、P2。

**写法 A（join，从 ⊥ 出发，⊤ = NAC）：**

| 轮次 | H.x = ⊔(1, P2.x) | P1.y | P2.x | 说明 |
|---|---|---|---|---|
| 初始 | ⊥ | ⊥ | ⊥ | 没有任何证人到场 |
| 第 1 轮 | ⊔(1, ⊥) = **1** | 2 | 2 | 只有外部传来的 1 |
| 第 2 轮 | ⊔(1, 2) = **⊤** | ⊤ | **2** | 绕回来的 2 与 1 冲突 |
| 第 3 轮 | ⊤ | ⊤ | 2 | 与上一轮相同，到达不动点 |

**写法 B（meet，从 ⊤ 出发，⊥ = NAC）：**

| 轮次 | H.x = ⊓(1, P2.x) | P1.y | P2.x | 说明 |
|---|---|---|---|---|
| 初始 | ⊤ | ⊤ | ⊤ | 没有任何证人到场 |
| 第 1 轮 | ⊓(1, ⊤) = **1** | 2 | 2 | 只有外部传来的 1 |
| 第 2 轮 | ⊓(1, 2) = **⊥** | ⊥ | **2** | 绕回来的 2 与 1 冲突 |
| 第 3 轮 | ⊥ | ⊥ | 2 | 与上一轮相同，到达不动点 |

两张表的数字完全一样，只有符号互换。最终结论如下：

| 程序点 | x | y |
|---|---|---|
| 循环头 H | NAC | — |
| P1（`y = x + 1` 之后） | NAC | NAC |
| P2（`x = 2` 之后） | **2** | NAC |

**注意 P2.x = 2**：循环头的 NAC 并没有“感染循环体里的所有人”，它遇到 `x = 2` 就被覆盖了。在 H 中，x 的值经历了 UNDEF → 1 → NAC，每一轮都朝保守端移动，然后停住。

### 3. 例二：不动点不唯一，起点决定精度

```c
x = 1;
while (c) {
    x = 2 - x;
}
```

运行时 x 永远是 1，因为 2 − 1 = 1。各程序点为：H（循环头）和 P（`x = 2 - x` 之后）。

**从起点端（UNDEF）出发：**

| 轮次 | H.x = 合并(1, P.x) | P.x = 2 − H.x |
|---|---|---|
| 初始 | UNDEF | UNDEF |
| 第 1 轮 | 1 | 1 |
| 第 2 轮 | 1 | 1，到达不动点 |

结论：**x 是常量 1。**

**从保守端（NAC）出发：**

| 轮次 | H.x = 合并(1, P.x) | P.x = 2 − H.x |
|---|---|---|
| 初始 | NAC | NAC |
| 第 1 轮 | NAC | NAC，已经是不动点 |

结论：“不知道”。

**两个状态都是不动点，都自洽**，但精度天差地别。原因在于循环“自己证明自己”：只要一开始假设 x 不确定，这个假设就会通过循环自我维持下去。

| | 写法 A | 写法 B |
|---|---|---|
| 从 UNDEF 出发得到的 | ⊥ 往上走到的第一个不动点：**最小不动点 LFP** | ⊤ 往下走到的第一个不动点：**最大不动点 MFP** |
| 它是什么 | 所有不动点中最精确的一个 | 所有不动点中最精确的一个 |

“最小”和“最大”只是画法不同带来的叫法差异，指的是**同一个答案**。

**直觉总结：从 UNDEF 出发，就像侦探不预设立场，只在证据迫使时才放弃精确性。** 迭代第 k 轮的结果，大致相当于“只考虑了绕环不超过若干圈的路径”。随着轮次增加，越来越多的真实路径被纳入考虑，直到再多考虑也不会改变结论。

### 4. 反例：不从起点出发，值会“往回走”

把例一的循环体改成 `x = 1`，并且**从 NAC 出发**：

| 轮次 | H.x = 合并(1, P2.x) | P2.x（`x = 1` 之后） |
|---|---|---|
| 初始 | NAC | NAC |
| 第 1 轮 | NAC | **1**（赋值覆盖） |
| 第 2 轮 | 合并(1, 1) = **1** | 1 |

H.x 从 NAC 变回了 1，**朝起点端移动了**。这说明“值只朝一个方向移动”不是单调性单独保证的，**必须从起点端出发**。另外，这个例子从 NAC 出发最终也得到了精确结果，因为赋值打破了自依赖。只有像例二那样的自依赖循环，才能展示“多个不动点”的现象。

## 六、最精确的不动点就是最优答案吗？不一定

理论上最理想的答案是 **MOP（Meet / Join Over all Paths）**：先沿每一条执行路径分别计算，最后再合并。迭代求得的不动点是“边走边合并”的结果，二者不一定相等。

```c
if (c) { a = 1; b = 2; }
else   { a = 2; b = 1; }
z = a + b;
```

- **逐路径计算（MOP）**：两条路径上 z 都是 3，所以 z = 3。
- **先合并再计算（不动点）**：a = 合并(1, 2) = NAC，b = NAC，所以 z = NAC。

| 分析类型 | 不动点与 MOP 的关系 |
|---|---|
| 可分配（distributive）的分析：活跃变量、到达定值、可用表达式 | 不动点 = MOP |
| 不可分配的分析：常量传播 | 不动点可能比 MOP 更保守（但仍然安全） |

所以要分清三件事：**终止、安全、最优精度**，它们是三个不同的问题。

## 七、总览图

```
           写法 A（join，向上）                 写法 B（meet，向下）
          ┌───────────────┐                  ┌───────────────┐
    NAC → │      ⊤       │                   │      ⊤       │ ← UNDEF（起点）
          │   ↑ 水位上涨  │                   │   ↓ 下楼梯    │
          │   常数层     │                   │   常数层     │
          │   ↑          │                   │   ↓          │
  UNDEF → │      ⊥       │                   │      ⊥       │ ← NAC
          └───────────────┘                  └───────────────┘
                 │                                 │
                 └─────────────┬───────────────────┘
                               ▼
     [格]                 定义结论的形状与合并规则
     [单调的 transfer]    输入越保守，输出不会越精确
     [从 UNDEF 出发]      保证同一程序点在迭代中只朝 NAC 方向移动
     [有限高度]           路程有尽头（无限高度时用 widening）
                               ▼
          必然停止，停在最精确的不动点（A 中称 LFP，B 中称 MFP）
          该不动点安全，但不一定等于 MOP
```

## 八、常见误区清单

| 误区 | 正确理解 |
|---|---|
| ⊤ 就是“未知”，⊥ 就是“冲突” | 含义取决于约定。用 UNDEF / NAC 这两个角色名理解最稳妥 |
| UNDEF 表示“可能是任何值” | 那是 NAC 的含义。UNDEF 表示“尚无信息到达” |
| 格是一棵树 | 格不是树。我们关心的是它的**高度** |
| 单调性就是“值只往一个方向走” | 单调性是函数的性质。“只往一个方向走”还需要从起点端出发 |
| 一旦是 NAC，后面的代码都变不回常量 | 只对**同一个程序点在迭代中**成立。沿着代码往下走，赋值会重置信息 |
| 冲突的 NAC 会感染整个循环体 | 赋值语句之后的程序点不受影响 |
| 每次迭代只会走一级 | 可能跨多级，例如 `x = read()` |
| 要防止分析器卡在用户的死循环里 | 分析不执行代码。迭代的必要性来自 CFG 中的环 |
| 有限高度加单调性保证结果正确 | 它们只保证**终止**。安全性取决于 transfer function 是否正确 |
| 不动点是唯一的 | 可能有多个。从起点端出发得到的是最精确的那个 |
| 最精确的不动点就是最优答案 | 对不可分配的分析（如常量传播），它可能比 MOP 更保守 |
| 最小不动点和最大不动点是两种不同的答案 | 写法 A 中的 LFP 和写法 B 中的 MFP 指的是同一个答案 |
| “⊤ 永远是安全的” | 真正的规律是“保守端是安全的”。哪一端是保守端，取决于约定和分析类型（may / must） |

---

## 九、给教学者的建议

1. **先用角色名，再引入符号。** 先讲 UNDEF / 常数 / NAC，等学生建立直觉后，再告诉他们“这本书把 UNDEF 叫作 ⊤，那本书叫作 ⊥”。
2. **先手算，再讲定理。** 让学生在纸上逐轮填写例一和例二的表格，亲眼看到“答案不再变化”的那一刻。
3. **一定要给出具体代码和程序点编号。** 没有代码的“传话故事”无法验证，很容易讲错。
4. **用例二讲清楚为什么从起点出发。** 它是展示“多个不动点”和“乐观初始化的价值”最简洁的例子。
5. **让学生把两种写法的表格对照着填一遍。** 填完会发现数字完全相同，从此不会再被方向约定困扰。

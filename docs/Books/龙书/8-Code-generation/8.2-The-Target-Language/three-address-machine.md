# 三地址机器（Three-Address Machine）技术说明文档

## 1. 概述

三地址机器是编译原理与计算机体系结构领域的经典抽象指令集模型，也是代码生成技术教学的基准目标机。其核心设计特征为：单条运算指令最多可独立指定**两个源操作数地址**与**一个结果目的地址**，运算过程不覆盖源操作数，指令语义规整、副作用少，与编译器三地址中间码（Three-Address Code）天然一一对应。

本文描述的模型对应经典编译教材中的标准目标机：基于加载-存储（Load-Store）架构，配备通用寄存器组，支持运算、跳转、条件跳转等完整指令类别，可覆盖绝大多数寄存器型CPU的代码生成基础逻辑。

## 2. 核心定义与指令格式

### 2.1 基本定义

三地址机器的命名源于运算指令的地址数量：每条算术/逻辑运算指令，最多包含3个独立的内存/寄存器地址引用，分别对应2个源操作数与1个目的操作数。运算完成后，源操作数的值保持不变，结果仅写入独立的目的地址，不存在「源操作数被结果覆盖」的隐式副作用。

### 2.2 标准运算指令格式

通用运算指令的语法格式为：

```
OP  dst, src1, src2
```

对应语义：
$$ dst = src_1 \ \mathbf{OP} \ src_2 $$

- `OP`：操作码，如加法`ADD`、减法`SUB`、乘法`MUL`等算术运算，或`AND`、`OR`等逻辑运算
- `src1`、`src2`：源操作数地址，可以是寄存器或内存单元（加载-存储架构下仅限寄存器）
- `dst`：结果目的地址，与源地址相互独立

### 2.3 典型示例

以减法指令为例：

```
SUB r1, r2, r3
```

执行语义为 `r1 = r2 - r3`：读取寄存器r2、r3中的值做减法运算，结果写入寄存器r1；运算全程不修改r2、r3的原值。

对于仅需单个操作数的一元运算（如取反、移位），指令退化为双地址格式，仅保留目的地址与一个源地址，无第二源操作数。

## 3. 完整指令集分类

标准三地址目标机的指令集分为四大类，覆盖程序运行的全部基础能力：

### 3.1 加载指令（Load Operations）

负责将内存中的数据载入寄存器，是内存数据参与运算的唯一入口。

- 基础格式：`LD dst, addr`
- 语义：`dst = addr`，将内存地址`addr`处的值写入目标位置`dst`
- 典型形态：
  - 内存到寄存器：`LD r, x`，将内存变量x的值加载到寄存器r
  - 寄存器到寄存器：`LD r1, r2`，将寄存器r2的值复制到寄存器r1

### 3.2 存储指令（Store Operations）

负责将寄存器中的结果写回内存，完成运算结果的持久化。

- 基础格式：`ST x, r`
- 语义：`x = r`，将寄存器r中的值写入内存地址x对应的单元

### 3.3 运算指令（Computation Operations）

执行算术、逻辑计算，是三地址格式的核心载体。所有运算仅在寄存器间完成，不直接操作内存，符合加载-存储架构规范。

### 3.4 跳转与条件跳转

- 无条件跳转（Jump Operations）：直接修改程序计数器，跳转到指定标号的指令位置，用于实现循环、无条件分支。
- 条件跳转（Conditional Jumps）：根据状态标志位（如零标志、符号标志、进位标志）判断是否跳转，用于实现if-else、循环条件判断等控制流逻辑。

## 4. 底层架构特性

### 4.1 字节可寻址内存

目标机采用字节可寻址（Byte-Addressable）内存模型：内存的最小寻址单元为1字节，多字节数据（如整型、浮点型）由连续字节拼接存储，地址指向数据的首字节。该模型与现代主流CPU的内存寻址方式完全一致。

### 4.2 通用寄存器组

硬件配备`n`个通用目的寄存器（General-Purpose Registers），编号为 `R0, R1, ..., Rn-1`。寄存器是CPU中速度最快的存储单元，也是运算指令的唯一操作数载体；寄存器数量有限，是代码生成中寄存器分配算法的核心资源。

### 4.3 加载-存储架构

该三地址机器遵循加载-存储（Load-Store）架构约束：

- 运算指令的操作数只能是寄存器，不能直接引用内存地址
- 内存数据必须先通过加载指令送入寄存器，运算完成后再通过存储指令写回内存
  该设计是现代RISC架构的核心特征，指令规整性强，适合流水线优化与编译器调度。

## 5. 与其他地址架构的横向对比

| 架构类型  | 典型运算指令格式             | 核心语义特征                           | 代表场景                            |
|:----- |:-------------------- |:-------------------------------- |:------------------------------- |
| 三地址机器 | `OP dst, src1, src2` | 双源操作数独立，结果写入独立目的地址，源值不被覆盖        | ARM、RISC-V、MIPS等RISC架构，编译原理教学模型 |
| 二地址机器 | `OP dst_src, src2`   | 目的地址同时作为第一源操作数，运算后原源值被结果覆盖       | x86 CISC架构主流运算指令                |
| 一地址机器 | `OP addr`            | 依赖累加器寄存器，运算为「累加器 OP 内存值」，结果回写累加器 | 早期累加器架构CPU                      |
| 零地址机器 | `OP`                 | 依赖操作数栈，从栈顶弹出操作数、结果压回栈顶           | JVM、WebAssembly等栈式虚拟机           |

## 6. 在编译代码生成中的核心价值

编译原理教材普遍选用三地址机器作为代码生成章节的目标机，核心原因有三点：

1. **与中间码天然对齐**：与三地址中间码 `x = y op z` 格式完全匹配，指令选择逻辑最简单，可将教学重点聚焦于寄存器分配、指令调度等核心算法，而非复杂指令集的特殊适配。
2. **架构代表性强**：本质是对现代RISC架构的抽象简化，掌握该模型的代码生成方法，可直接迁移到ARM、RISC-V等真实硬件的编译优化场景。
3. **语义无副作用**：指令规则统一，无隐式的源操作数覆盖、专用寄存器约束等例外情况，适合作为图着色寄存器分配、最优求值顺序等经典算法的验证载体。

## 7. 局限性说明

三地址机器是理想化的抽象模型，真实硬件会在此基础上增加约束与扩展：

- 真实RISC架构通常保留三地址的核心形态，但会新增立即数寻址、偏移寻址等多种寻址模式，部分指令存在专用寄存器约束（如乘法、除法的固定寄存器对）
- x86等CISC架构以二地址指令为主，不严格遵循三地址规范，代码生成时需要额外处理「源操作数覆盖」的问题

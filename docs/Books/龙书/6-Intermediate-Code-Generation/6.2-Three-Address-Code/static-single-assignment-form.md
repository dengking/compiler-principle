# 静态单赋值形式（Static Single-Assignment Form, SSA）技术文档

see also: wikipedia [Static single-assignment form](https://en.wikipedia.org/wiki/Static_single-assignment_form)

## 1. 概述

**静态单赋值形式（Static Single-Assignment Form, SSA）** 是一种在三地址码基础上发展出的**中间表示（IR）**。它在保留三地址码基本结构的同时，通过一条核心约束显著增强了 IR 对**代码优化**的支持能力：

> **在 SSA 形式中，每个变量恰好只被赋值一次（静态意义上）。**

"静态"（static）一词强调的是**在程序文本中**每个变量只有一处赋值定义，而非运行时只执行一次（循环中同一条赋值语句在运行时仍可能被多次执行）。

SSA 是现代优化编译器（如 LLVM、GCC 的 GIMPLE-SSA）的核心中间表示，广泛应用于常量传播、死代码消除、值编号等优化。

---

## 2. SSA 的两大核心特征

SSA 与普通三地址码的区别体现在两个方面：

### 2.1 所有赋值都针对不同名字的变量

在普通三地址码中，同一个变量可以被多次赋值。而在 SSA 中，每次赋值都会创建一个**带下标的新版本变量**。

**普通三地址码：**

```
p = a + b
p = p * c
p = p - d
```

变量 `p` 被赋值三次，难以区分某处引用的是哪一次的值。

**转换为 SSA 形式：**

```
p1 = a  + b
p2 = p1 * c
p3 = p2 - d
```

每次赋值产生一个新版本（`p1`、`p2`、`p3`），每个版本**只被定义一次**。任何一处对 `p` 的引用都明确对应到某个特定版本，**值的来源变得完全清晰**。

### 2.2 使用 φ 函数（phi-function）合并控制流

上述单赋值约束在**顺序代码**中容易满足，但当**控制流汇合**时会遇到问题。

**问题场景**：考虑如下带分支的代码：

```
        if (flag) 
            x = 1;
        else 
            x = 2;
        y = x + 3;
```

转换为 SSA 时，两个分支分别产生 `x1 = 1` 和 `x2 = 2`。但在汇合点计算 `y` 时，究竟该用 `x1` 还是 `x2`？**这取决于运行时实际走了哪条分支，编译时无法确定。**

**解决方案——φ 函数**：SSA 引入特殊的 **φ 函数**来"合并"来自不同控制流路径的多个版本：

```
        if (flag) 
            x1 = 1;
        else 
            x2 = 2;
        x3 = φ(x1, x2);   ← 汇合点插入 φ 函数
        y1 = x3 + 3;
```

**φ 函数的语义**：

- `x3 = φ(x1, x2)` 表示：如果控制流从第一条路径（`if` 分支）到达此处，则 `x3` 取 `x1` 的值；如果从第二条路径（`else` 分支）到达，则取 `x2` 的值。
- φ 函数总是位于**基本块的开头**（控制流汇合处）。
- 它是一种**概念上的**操作，本身不对应实际机器指令；在最终代码生成前，会通过"消除 SSA"阶段将其转化为普通的赋值或寄存器移动。

## 3. SSA 与三地址码的对比

| 维度        | 普通三地址码     | SSA 形式           |
| --------- | ---------- | ---------------- |
| **赋值约束**  | 变量可多次赋值    | 每个变量（版本）静态上仅赋值一次 |
| **变量命名**  | 复用同一名字     | 每次赋值创建带下标的新版本    |
| **值的来源**  | 需数据流分析才能确定 | 由变量名直接、唯一确定      |
| **控制流汇合** | 无需特殊处理     | 引入 φ 函数合并多版本     |
| **优化友好度** | 一般         | 高（定义-使用关系显式化）    |

---

## 4. SSA 的优势

### 4.1 定义-使用关系显式化

在 SSA 中，每个变量版本只有**唯一的定义点**。因此，某处对变量的每一次使用，都能立刻追溯到其唯一的定义，无需复杂的数据流分析来确定"这个值从哪里来"。这种**清晰的 def-use 关系**是众多优化的基础。

### 4.2 简化优化算法

许多经典优化在 SSA 下变得更简单、更高效：

- **常量传播（Constant Propagation）**：由于每个版本只定义一次，若某版本被赋为常量，则可直接将其所有使用替换为该常量。
- **死代码消除（Dead Code Elimination）**：若某版本从未被使用，可直接删除其定义。
- **全局值编号（Global Value Numbering）**：唯一命名使得等价表达式的识别更为直接。

### 4.3 稀疏数据流分析

> see also: wikipedia [Sparse conditional constant propagation](https://en.wikipedia.org/wiki/Sparse_conditional_constant_propagation)

SSA 使得数据流信息能够**沿 def-use 链直接传播**，而无需在每个程序点保存完整信息，从而实现更高效的"稀疏"分析。

## 5. 示例：完整的 SSA 转换

**源代码：**

```c
        a = x + y;
        b = a - 1;
        if (b > 0)
            a = b * 2;
        c = a + b;
```

**SSA 形式：**

```
        a1 = x  + y
        b1 = a1 - 1
        if b1 > 0 goto L
        goto NEXT
    L:  a2 = b1 * 2
    NEXT:
        a3 = φ(a1, a2)     ← 合并两条路径上的 a
        c1 = a3 + b1
```

**分析：**

- `a` 在源代码中有两次赋值，SSA 中分别成为 `a1`、`a2`。
- 由于 `a2 = b1 * 2` 只在 `if` 成立时执行，汇合点用 `a3 = φ(a1, a2)` 合并。
- 最终 `c1` 明确使用汇合后的版本 `a3`，值来源清晰无歧义。

## 6. 总结

| 要点         | 内容                            |
| ---------- | ----------------------------- |
| **定义**     | 每个变量在静态程序文本中恰好赋值一次的中间表示       |
| **"静态"含义** | 指程序文本中唯一定义，而非运行时执行一次          |
| **核心特征 1** | 每次赋值创建带下标的新版本变量               |
| **核心特征 2** | 用 φ 函数合并控制流汇合处的多个版本           |
| **φ 函数**   | 根据到达路径选择相应版本值，位于基本块开头，非实际机器指令 |
| **主要优势**   | 定义-使用关系显式化，大幅简化常量传播、死代码消除等优化  |
| **应用**     | LLVM、GCC 等现代优化编译器的核心 IR       |

**核心结论**：静态单赋值形式通过"每个变量仅赋值一次"的约束和 φ 函数机制，将变量的定义-使用关系彻底显式化。这一设计使得值的来源变得唯一而清晰，极大简化并加速了各类代码优化，因而成为现代优化编译器不可或缺的中间表示形式。

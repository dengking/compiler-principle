# 深度学习编译器的"万能锤"

**先给结论**
 
DL 编译器**没有引入很多新锤子**——它做的事更有趣：**把前三轮那批锤子的权重彻底重排了。** 有些锤子从核心降为边缘（不动点迭代几乎失业），有些从边缘升为核心（多面体模型、搜索、模调度、重物化），只有三样东西是**真正新的**。
 
|        | 锤子                                | 一句话                                                 | 前三轮的对应物                       |
| ------ | --------------------------------- | --------------------------------------------------- | ----------------------------- |
| **主锤** | **仿射循环嵌套 + 调度变换**（Einsum / 结构化算子） | 一切算子都是"仿射迭代空间上的循环嵌套"，一切优化都是对同一对象的调度选择               | 后端大锤⑤**从边缘升为中心**              |
| 大锤 ①   | **算法/调度分离 + 搜索**                  | 把"优化"变成"在显式设计的空间里搜索"                                | 后端大锤⑥**从兜底升为主力**              |
| 大锤 ②   | **算术强度 / 屋顶线**                    | 目标函数的重心从"算得少"变成"搬得少"                                | ★ **真正新的（目标函数换了）**            |
| 大锤 ③   | **标注传播 + 边界转换插入**                 | layout / sharding / 精度 / 存储空间 / 设备放置，全是同一个 DAG 标注问题 | 后端主锤 + 最小割岛屿，**从岛屿变成大陆**      |
| 大锤 ④   | **自动微分 = 线性映射转置 = 反向数据流**         | 反向模式 AD 就是把 DAG 的边反向；存哪些中间量 = 溢出 vs 重算              | ★ **真正新的（但内核是老的）**            |
| 大锤 ⑤   | **图重写 / 等价饱和 / 部分等价变换**           | 张量代数上的重写，外加"允许不等价 + 补偿"这一新招                         | 后端大锤②的推广                      |
| 大锤 ⑥   | **数值松弛：等价 → 容差**                  | 正确性不再是等价关系，而是一个带 ε 的偏序                              | ★ **真正新的（且它打破了 §H）**          |
| 大锤 ⑦   | **集合通信代数 + 流水线 = 模调度**            | 分布式并行进了编译器；流水线并行就是图级别的软件流水                          | 后端大锤④，**从 VLIW 冷知识变成千卡训练的核心** |
 
而最值得注意的一点是：**DL 程序是一个静态 DAG，没有控制流环。** 于是根据第三轮 §D.3 的结论——**"无环则折叠一遍，有环才需迭代"**——后端的主锤（不动点迭代）在 DL 编译器里几乎完全退化为单遍折叠。**这是那条结论最强的实证。**

## 0. DL 编译器为什么不一样：五条结构性差异

| 维度       | 标量编译器（C/Rust/Java） | DL 编译器（XLA/TVM/Inductor/MLIR）          |
| -------- | ------------------ | -------------------------------------- |
| **程序结构** | CFG 有环；过程间有递归      | **静态数据流 DAG，几乎无控制流** ⇒ 不动点迭代基本失业       |
| **规模分布** | 10⁵ 条指令，每条 ~1 周期   | 10³ 个算子，**每个算子 10⁹ 次浮点运算** ⇒ 优化的粒度完全不同 |
| **主要开销** | 指令数、分支预测、寄存器压力     | **内存带宽**（HBM ↔ SRAM ↔ 寄存器） ⇒ 目标函数换了    |
| **参数化**  | 值未知（`n` 是符号）       | **形状是少量整数，且常常编译期已知** ⇒ 偏求值的收益极大        |
| **语义**   | 位精确等价              | **数值容差** ⇒ 正确性的定义变了                    |
| **额外任务** | ——                 | **自动微分**、**分布式切分**、**量化** 全在编译器里       |

**由此可以预测（并被证实）DL 编译器长成什么样**：

```
无环 DAG           ⇒ 分析退化为单遍折叠；主要难度不在"分析"而在"选择"
算子内部规模巨大    ⇒ 优化的主战场是"单个算子内部的循环嵌套"，而非"算子之间"
带宽主导           ⇒ 融合（避免落盘中间量）和分块（提升复用）成为第一等公民
形状编译期已知      ⇒ 完全展开、特化、常量传播的收益极大（Futamura 大丰收）
数值容差           ⇒ 形式验证不可用，退化为差分测试 + 容差
AD + 分布式        ⇒ 引入了两类标量编译器没有的变换
```

## 主锤：仿射循环嵌套 + 调度变换

### 骨架

> **每一个 DL 算子，都是一个仿射迭代空间上的循环嵌套 + 仿射访存映射。**
> **每一个 DL 优化，都是对这同一个对象的一次调度选择。**

标准形式（Einsum / 索引记法 / linalg 的 `indexing_maps`）：

```
迭代空间：  I = { (i, j, k) : 0 ≤ i < M, 0 ≤ j < N, 0 ≤ k < K }
迭代类型：  i: parallel, j: parallel, k: reduction
访存映射：  A: (i,j,k) ↦ (i,k)
            B: (i,j,k) ↦ (k,j)
            C: (i,j,k) ↦ (i,j)
计算体：    C[i,j] += A[i,k] * B[k,j]
```

**这三样东西（迭代域 + 访存映射 + 迭代类型）就是算子的完整语义。** 一旦如此表示，下面这些"看起来完全不同的优化"就全部是同一件事：

| 优化                          | 调度变换                        |
| --------------------------- | --------------------------- |
| **循环分块 / tiling**           | 迭代域引入额外维度 `(i/T, i%T)`      |
| **循环交换 / reorder**          | 调度矩阵左乘置换矩阵                  |
| **向量化**                     | 把最内维标记为 `vectorized`        |
| **并行化 / 绑定到 GPU 线程**        | 把某维绑定到 `blockIdx/threadIdx` |
| **算子融合**                    | **合并两个算子的迭代域，把中间量的存储层级下移**  |
| **布局变换**                    | 改访存映射（而非改计算）                |
| **展开 / unroll**             | 完全展开某维                      |
| **缓存到 SRAM / `cache_read`** | 在某个循环层级插入一次数据搬运             |
| **张量化 / `tensorize`**       | 把一个子迭代域替换为一条硬件指令（MMA/DMA）   |
| **重物化 / 重算**                | 在需要处重新展开生产者的迭代域             |
| **切分到多设备 / sharding**       | 迭代域按某维分割 + 边界插入集合通信         |

> **这就是第三轮 §9（"统一多个 ad-hoc 机制"）母题的极致形态**，和 Parr 的 `Lexing = Parsing = Tree Parsing`、多面体模型统一循环变换，是同一类成就。收益也相同：**融合/分块/向量化/并行化各实现一次，所有算子共享。**

### 关键设计点：结构化算子（structured ops）

MLIR `linalg` 的做法值得单独讲，因为它是"换表示以消灭分析"（第三轮机制 III）的教科书实例。

```mlir
// 一个 matmul：语义完全由 indexing_maps + iterator_types 给出
linalg.generic {
  indexing_maps = [affine_map<(i,j,k) -> (i,k)>,     // A
                   affine_map<(i,j,k) -> (k,j)>,     // B
                   affine_map<(i,j,k) -> (i,j)>],    // C
  iterator_types = ["parallel", "parallel", "reduction"]
} ins(%A, %B) outs(%C) { ^bb(%a, %b, %c): ... }
```

**对比两种 IR 设计**：

|      | 命名算子 IR（TF GraphDef / ONNX / 早期 HLO）                 | 结构化算子 IR（linalg）                      |
| ---- | ---------------------------------------------------- | ------------------------------------- |
| 算子语义 | 藏在算子名字里（`Conv2D`、`BatchMatMul`…）                     | **显式写在 `indexing_maps` 里**            |
| 实现融合 | 必须为**每一对**算子写模式（`Conv+BN`、`Conv+ReLU`、…）⇒ `O(n²)` 规则 | **一份通用的融合实现**：检查两个 map 是否可组合 ⇒ `O(1)` |
| 新增算子 | 要重写所有 pass                                           | 只要能写出 map，自动获得全部变换                    |
| 类比   | 非 SSA IR：def-use 需要分析                                | **SSA：def-use 直接编码在 IR 里**            |

> **`indexing_maps` 之于融合/分块，正如 SSA 之于到达定值分析**——都是"把本来要靠分析得到的信息，直接编码进表示"。这解释了为什么 MLIR 生态愿意为 `linalg` 付出如此高的抽象成本。

### 抽象层次的选择：这是 DL 编译器最大的设计争议

第三轮 §J 说"归约的代价永远是信息丢失，现代趋势是推迟丢失"。DL 编译器把这条原则做成了公开的路线之争：

| 层次             | 代表                           | 程序员写什么               | 编译器搜什么           | 病理              |
| -------------- | ---------------------------- | -------------------- | ---------------- | --------------- |
| **库调用**        | cuDNN / cuBLAS / oneDNN      | 算子调用                 | 基本不搜（查表选 kernel） | **无法融合**；新算子等厂商 |
| **图 + 固定融合规则** | 早期 XLA / TensorRT            | 计算图                  | 融合分组             | 融合模式需人工枚举       |
| **张量表达式 + 调度** | Halide / TVM / TC            | 算法（Einsum）           | **完整调度空间**       | 搜索空间巨大、编译慢      |
| **块级 SPMD**    | **Triton** / Pallas / Mosaic | **tile 级程序**（已含分块决策） | 只搜 tile 内布局/流水   | 需要程序员懂硬件；但空间小得多 |
| **模板库**        | CUTLASS / Mojo               | 模板参数                 | 参数（或不搜）          | 专家门槛高，但性能天花板最高  |

> **Triton 的取舍值得特别注意**：它**放弃了"自动决定分块"**，让程序员写 tile 级代码，编译器只负责 tile 内部（合并访存、共享内存、layout 转换、软件流水、MMA 映射）。
> 
> ```
> Halide/TVM：  抽象层高 → 搜索空间大 → 需要强搜索器 + 好代价模型（常常失灵）
> Triton：      抽象层适中 → 搜索空间小 → 编译器只做"确定性好做"的部分
> ```
> 
> 这是"**何时承诺**"母题（第三轮 §9 主题三）在抽象层次上的版本：**Triton 让程序员早承诺（分块），换取编译器不必赌。** 而 Triton 的成功很大程度上说明——在代价模型不可靠时，**缩小搜索空间比强化搜索器更有效**。

### 连线

```
仿射表示 ← 后端大锤⑤（多面体模型），从边缘升为中心
indexing_maps ≡ SSA        → 换表示以消灭分析（机制 III）
tensorize ≡ 指令选择        → 后端大锤③（把一个子树替换为一条复杂指令）
抽象层次之争 ≡ 何时丢弃信息  → 第三轮 §J
Triton 缩小空间 ≡ 早承诺     → 第三轮 §9 主题三
```

## 大锤①：算法/调度分离 + 搜索

### 骨架

```
程序 = 算法（计算什么，程序员写，语义固定）
     ⊗ 调度（怎么计算，可搜索，不影响语义）
```

Halide 的这一刀是 DL 编译器最重要的架构决定。它把"编译器优化"这件不可控的事，变成了一个**有明确定义的搜索问题**：

```
搜索空间 = 合法调度的集合（由调度原语的组合定义）
目标函数 = 真机执行时间（或代价模型的预测）
求解方法 = 搜索
```

### 四代演进

| 代              | 做法            | 代表                                                                          | 问题                 |
| -------------- | ------------- | --------------------------------------------------------------------------- | ------------------ |
| **手写调度**       | 程序员写调度        | Halide 原版、TVM TE schedule                                                   | 专家依赖；每个硬件重写        |
| **模板 + 参数搜索**  | 专家写模板留旋钮，搜参数  | **AutoTVM**、Mullapudi 自动调度器                                                 | 模板本身仍需专家；空间受模板限制   |
| **无模板搜索**      | 从算法自动派生候选调度骨架 | **Ansor**（sketch 派生 + 随机标注 + 演化搜索 + 学习代价模型）、Halide Adams 2019（束搜索 + 学习代价模型） | 搜索成本高（小时级）；代价模型泛化差 |
| **搜索 + 专家微内核** | 编译器管外层，专家写内层  | TVM `tensorize`、CUTLASS + 生成器、Triton `tl.dot` → MMA                         | 目前的工程最优点           |

**Ansor 的结构值得拆开看，因为它把前三轮的四把锤子拼在了一起**：

```
① 骨架派生（sketch generation）：按派生规则枚举"结构性决策"
     ← 这是有界的、可枚举的：判定树/枚举（§G）
② 随机标注（annotation）：填入 tile 大小、unroll 因子等数值参数
     ← 连续/大基数参数，不可枚举 ⇒ 采样
③ 演化搜索 + 学习代价模型（XGBoost on 特征化调度）
     ← 后端大锤⑥
④ 任务调度器：在多个子图之间按"梯度"分配搜索预算
     ← 这是一个资源分配问题（后端大锤④），目标是最小化端到端时间
```

> **注意 ①/② 的分工**：**结构性决策枚举，数值参数采样。** 这与"BURG 预计算表（结构）+ 运行时 DP（代价）"、"判定树（结构）+ PGO 重排（频率）"是同一个分工模式——**离散结构用穷举，连续参数用搜索**。

### 深层洞察

> **洞察一：算法/调度分离是"合法性与收益性分离"的制度化。**
> 
> 第三轮说后端有三层：合法性（不动点分析）、等价性（等价类）、收益性（DP/图/搜索）。Halide 的贡献是**用类型系统级别的手段保证前两层**：
> 
> ```
> 调度原语被设计为"保语义的"（split/reorder/vectorize/parallel 都不改变结果）
> ⇒ 合法性由构造保证（by construction），不需要分析
> ⇒ 搜索器可以肆无忌惮地探索，绝不会产生错误程序
> ```
> 
> **这是把"证明每次变换正确"（§H 模拟关系）替换为"只允许可证明正确的变换"。** 前者是事后验证，后者是设计时保证——正如强类型语言用类型系统排除一整类错误，而不是靠事后分析。
> 
> 代价：**调度语言的表达力上限就是优化的上限。** 见 §10。

> **洞察二：代价模型的不可靠性，在 DL 里比标量编译器严重得多。**
> 
> | 因素     | 标量编译器          | DL 编译器                                                    |
> | ------ | -------------- | --------------------------------------------------------- |
> | 关键量    | 指令数、延迟（手册有）    | **带宽利用率、cache/SRAM 命中、bank 冲突、occupancy、tensor core 利用率** |
> | 可否解析建模 | 部分可以（llvm-mca） | **基本不行**（GPU 微架构不公开、行为高度非线性）                              |
> | 因此     | 解析模型 + 少量 PGO  | **必须实测**（autotuning 是刚需，不是奢侈品）                            |
> 
> 于是 DL 编译器普遍采用**三级代价来源**：
> 
> ```
> 解析模型（屋顶线、占用率计算器）  → 快，粗，用于剪枝
> 学习模型（XGBoost / GNN / TLM）   → 中，需训练数据，泛化性是死穴
> 真机测量                          → 慢（毫秒~秒/次），但是 ground truth
> ```
> 
> 这与第三轮"好的近似必须配可检测的失败信号"呼应：**真机测量就是那个信号**。学习代价模型之所以危险，正是因为它**预测错了不会报错**。

> **洞察三：调优结果的缓存 = §E + §I 在最粗粒度上的重现。**
> 
> ```
> key   = (算子语义, 形状, 硬件型号, 编译器版本)
> value = 最优调度 / 编译好的 kernel
> ```
> 
> TVM 的 tuning log、Triton 的 autotune cache、PyTorch Inductor 的 `FX graph cache` + 远程缓存、JAX 的持久化编译缓存——**全是记忆化**。而"key 该多细"（要不要按形状特化？按 batch size？）就是第三轮 §I 说的"key 粒度"权衡，且答案同样是：**太粗 ⇒ 命中但不优；太细 ⇒ 不命中，冷编译爆炸**。

### 连线

```
算法/调度分离 → 合法性 by construction（替代 §H 的事后验证）
sketch + 标注 → 离散穷举 + 连续采样（结构/参数分工）
学习代价模型  → 后端大锤⑥；且是"无失败信号"的危险近似
调优缓存      → §E hash-consing + §I 记忆化，粒度=整个 kernel
Triton 的选择 → 缩小空间 > 强化搜索器（在代价模型不可靠时）
```

## 大锤②：算术强度 —— 目标函数的重心迁移

**这是 DL 编译器第一样真正新的东西：不是新方法，而是新目标。**

### 骨架

```
算术强度  I = FLOPs / Bytes_moved            (单位: FLOP/Byte)

屋顶线：  可达性能 = min( 峰值算力,  I × 内存带宽 )

⇒ 若 I < 峰值算力/带宽（"脊点"），则程序是 memory-bound，
  优化的唯一目标是提高 I —— 也就是"减少数据搬运"，而不是"减少计算"
```

现代加速器的脊点极高（H100 的 `峰值FLOPS/HBM带宽` ≈ 300+ FLOP/Byte），而大多数 DL 算子的原生算术强度远低于此：

| 算子                        | 原生算术强度          | 状态                            |
| ------------------------- | --------------- | ----------------------------- |
| element-wise（ReLU、add）    | ~0.25 FLOP/Byte | **极度 memory-bound**           |
| LayerNorm / Softmax       | ~1              | memory-bound                  |
| GEMM `M×K×N`（大方阵）         | `~min(M,N,K)/3` | compute-bound（若够大）            |
| GEMV / batch=1 解码         | ~0.5            | **memory-bound**（LLM 推理的核心困境） |
| Attention（未融合）            | ~1（受中间矩阵落盘拖累）   | memory-bound                  |
| Attention（FlashAttention） | 高               | compute-bound ✔               |

### 由此推出的三条设计定律

> **定律一：融合的目的不是省调用开销，而是不让中间量落到 HBM。**
> 
> ```
> 未融合：  y = relu(x)      → 读 x（N 字节），写 y（N 字节）
>           z = y * 2        → 读 y（N 字节），写 z（N 字节）
>           总搬运 4N，FLOPs 2N，I = 0.5
> 融合：    z = relu(x) * 2  → 读 x，写 z
>           总搬运 2N，FLOPs 2N，I = 1.0     ⇒ 2× 加速
> ```
> 
> **这与标量编译器里的"内联"完全不同**：内联省的是调用开销（几个周期），融合省的是**整个中间张量的读写**（可能是 GB 级）。所以在 DL 编译器里，**融合是第一优化**，其他都排后面。
> 
> 融合决策的形式化：**图划分问题**（把 DAG 切成若干子图，每个子图编译为一个 kernel），目标是最小化跨子图的数据量 + 满足 SRAM 容量约束 ⇒ **NP-hard**。工程解法照旧三条路：
> 
> ```
> ① 贪心 + 规则（XLA 的 kLoop/kInput/kOutput 融合启发式；Inductor 的调度器）
> ② 树/链上 DP（若图退化为树）
> ③ ILP（编译时间换质量）
> ```

> **定律二：分块（tiling）是提高算术强度的唯一通用手段，且必须递归应用。**
> 
> ```
> 对 M×N×K 的 GEMM，若整体做：搬运 O(MK+KN+MN)，FLOPs O(MNK)，I = O(MNK/(MK+KN+MN))
> 若分块为 T×T×T 的小块，每块在片上完成：
>     块内 I = T³ / (3T²) = T/3        ⇒ 块越大，强度越高
>     约束：3T² ≤ SRAM 容量            ⇒ T ≤ sqrt(SRAM/3)
> ⇒ 最优 tile 尺寸由片上容量直接决定（这就是 CUTLASS 的核心方程）
> ```
> 
> 而现代硬件有 4~5 级存储（寄存器 / shared memory / L2 / HBM / 节点间网络），所以**分块必须每一级做一次**——这就是 CUTLASS 的"分层 GEMM"结构，也是 Alpa/Megatron 的"分层并行"结构。
> 
> **递归分块 = 同一把锤子在存储层级上重复施加。** 这与第三轮 §J 的"逐层降级"同构，只是这里的"层"是**存储层级**而非**抽象层级**。

> **定律三：当带宽是瓶颈时，"重算"比"存取"便宜 —— 于是重物化从冷知识变成核心技术。**
> 
> ```
> 标量编译器：  重物化（rematerialization）是寄存器分配的一个小技巧
>              （Briggs 等：常量/地址计算宁可重算，不要溢出到栈）
> DL 编译器：   梯度检查点（gradient checkpointing）= 完全同一件事
>              前向的激活值不存，反向时重新算
>              内存 O(n) → O(√n) 或 O(log n)，代价是 1.3~2× 计算
> ```
> 
> 这条在 §大锤④ 详述。这里只强调**动机的同一性**：
> 
> ```
> 溢出（spill）  = 存到更慢的存储      成本 = 带宽
> 重算（remat）  = 重新计算            成本 = 算力
> 当"算力/带宽"比值很高时，重算必然胜出 —— 而这正是现代加速器的特征
> ```
> 
> **所以"梯度检查点"不是一个 DL 特有的技巧，而是"寄存器分配的溢出决策"在算力/带宽比极端化后的必然结论。**

### 连线

```
算术强度 → ★ 新的目标函数（真正新的东西）
融合 = 图划分 NP-hard → 后端大锤④的三条老出路
分块 = 提高强度的通用手段，递归应用 → §J 逐层降级（层=存储层级）
重物化 = 溢出 vs 重算 → 后端大锤④（寄存器分配），因算力/带宽比而反转
```

## 大锤③：标注传播 + 边界转换插入

### 骨架

> **给 DAG 的每个节点选一个"标注"，使得节点自身代价 + 相邻节点标注不同时的转换代价之和最小。**

```
输入： DAG (V, E)
       每个节点 v 的候选标注集合 L(v)
       节点代价 c(v, ℓ)         —— 该节点在标注 ℓ 下的执行代价
       边转换代价 t(u→v, ℓᵤ, ℓᵥ) —— 标注不一致时需插入的转换算子代价
       部分节点标注被固定（入口/出口/用户标注/硬件约束）

求：   标注 ℓ : V → L 使总代价最小
```

**这个问题在 DL 编译器里出现了至少六次，每次都被当成"一个独立的 pass"来实现——但它们是同一个问题。**

### 六个实例

| 实例          | 标注是什么                                                    | 边界要插入什么                                                       | 代表实现                                                             |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- |
| **布局分配**    | `NCHW` / `NHWC` / `NCHWc8` / tiled / MMA fragment layout | `transpose` / `copy` / `convert_layout`                       | XLA layout assignment；**Triton 的 layout 系统**；TVM `AlterOpLayout` |
| **切分/分片传播** | sharding spec（每个张量维度切到哪个 mesh 轴）                         | `all-gather` / `reduce-scatter` / `all-to-all` / `all-reduce` | **GSPMD**、JAX `shard_map`、PyTorch DTensor                        |
| **精度/量化分配** | `fp32` / `bf16` / `fp8` / `int8` + scale                 | `quantize` / `dequantize` / `cast`                            | TensorRT、AMP、量化工具链                                               |
| **存储空间分配**  | HBM / SRAM / 寄存器 / L2                                    | DMA / `cache_read` / `copy`                                   | TPU/NPU 编译器、Pallas                                               |
| **设备放置**    | device id                                                | `send` / `recv` / `d2d copy`                                  | 早期 TF placement、模型并行                                             |
| **稀疏/格式选择** | dense / CSR / block-sparse / ragged                      | 格式转换                                                          | 稀疏编译器（TACO、SparseTIR）                                            |

### 深层洞察

> **洞察一：这就是后端主锤 + 最小割岛屿，只是从"岛屿"变成了"大陆"。**
> 
> 求解方法完全对应：
> 
> | 方法           | 用在哪                                       | 性质                            |
> | ------------ | ----------------------------------------- | ----------------------------- |
> | **双向传播到不动点** | GSPMD 的 sharding propagation；XLA layout   | 后端主锤；**因为 DAG 无环，通常 1~2 遍收敛** |
> | **最小割**      | 二元标注（如 `NCHW` vs `NHWC`）⇒ **s-t 最小割精确最优** | 第三轮的"NP-hard 汪洋中的岛屿"          |
> | **ILP**      | 多元标注 + 复杂约束（Alpa 的 intra-op 并行）           | 编译时间换最优                       |
> | **贪心 + 优先级** | 大多数工业实现                                   | 快，可能次优                        |
> | **DP**       | 若 DAG 是链/树（如流水线阶段划分）                      | 最优                            |
> 
> **"二元标注 ⇒ 最小割最优"值得记住**：这与后端 PRE 的最小割公式化是同一个结构（节点二分 + 边界代价 = 割容量）。所以：**如果你的标注只有两种选择，不要写启发式，直接建图跑最大流。**

> **洞察二：GSPMD 的 sharding 传播就是"标注传播"的教科书实现，且它揭示了这类问题的通用架构。**
> 
> ```
> ① 用户在少数张量上标注 sharding（部分固定的标注）
> ② 沿 DAG 双向传播：
>      前向：由输入的 sharding 推出输出的 sharding
>      反向：由输出的 sharding 推出输入的 sharding
>    每个算子提供一组"传播规则"（如 matmul 的 (i,k)×(k,j)→(i,j) 如何映射切分）
> ③ 迭代到不动点（冲突时按优先级/启发式裁决）
> ④ Partitioner：对每条 sharding 不一致的边，插入相应的集合通信
> ```
> 
> **对照 XLA layout assignment**：
> 
> ```
> ① 入口/出口 layout 固定（ABI），某些算子有 layout 偏好（卷积偏好 NHWC）
> ② 沿 DAG 双向传播 layout 约束
> ③ 迭代到不动点
> ④ 对不一致的边插入 transpose/copy
> ```
> 
> **两个 pass 的结构逐字对应。** 而它们在工业代码里是两套完全独立的实现——这正是"没有认出锤子"的代价。
> 
> 顺带一个漂亮的观察：**算子的 sharding 传播规则，就是它的 `indexing_maps`。**
> 
> ```
> matmul 的 indexing_maps: A:(i,k)  B:(k,j)  C:(i,j)
> ⇒ 若沿 i 切分：A 沿 0 维切，C 沿 0 维切，B 不切          （数据并行）
> ⇒ 若沿 j 切分：B 沿 1 维切，C 沿 1 维切，A 不切          （列并行）
> ⇒ 若沿 k 切分：A 沿 1 维切，B 沿 0 维切，C 需 all-reduce  （规约维切分）
> ```
> 
> **切分规则 = 迭代域按某维分割 + 该维是否 reduction 决定要不要通信。**
> 于是主锤（仿射表示）**自动推导出**了大锤③的传播规则——这是"结构化算子"设计最大的回报，也是 Megatron 那些手工推导的"行并行/列并行"的自动化版本。

> **洞察三：内存规划（buffer assignment）是这类问题的近亲，但结构关键性地不同。**
> 
> ```
> 寄存器分配： 值的活跃区间 → 干扰图 → k-着色         （所有寄存器同样大）
> 张量内存规划：张量的活跃区间 → 在一段连续内存上分配偏移  （张量大小差异巨大）
> ```
> 
> 这不是着色，而是 **动态存储分配（DSA）/ 二维条带装箱**：
> 
> ```
> 横轴 = 时间（执行顺序确定后，每个张量占一个区间）
> 纵轴 = 内存偏移（每个张量占一段长度 = 其大小）
> 求：把所有矩形无重叠地塞进最小高度的条带
> ⇒ NP-hard；已知常数因子近似（Buchsbaum 等 2+ε）
> ⇒ 工业实现：按大小降序的 first-fit / best-fit（"greedy by size"）
> ```
> 
> **精确的差异**：
> 
> |       | 寄存器分配             | 张量内存规划                      |
> | ----- | ----------------- | --------------------------- |
> | 资源单位  | 同质（1 个寄存器）        | **异质（字节数差 6 个数量级）**         |
> | 干扰结构  | 一般图（SSA 下弦图）      | **区间图**（执行序固定后）             |
> | 问题类型  | 图着色               | **条带装箱 / 偏移分配**             |
> | 复杂度   | NP-hard（SSA 下多项式） | **NP-hard（即使区间图，因为大小异质）**   |
> | 溢出的替代 | 存栈 / 重物化          | **重物化（检查点）/ offload 到 CPU** |
> 
> **这是"资源同质性"如何改变问题类别的清晰案例**：把资源从"同质"变成"异质"，弦图的好性质立刻失效，问题从着色变成装箱。反过来也说明第三轮 §5.3 的"弦图最优"结论有多脆弱——它依赖"所有寄存器一样大"这个隐含前提。

### 连线

```
标注传播 → 后端主锤（DAG 上 1~2 遍收敛，因为无环）
二元标注 → 最小割精确最优（PRE 的同构问题）
多元 + 约束 → ILP（Alpa）
传播规则 ← 主锤的 indexing_maps 自动导出（结构化算子的回报）
内存规划 → 后端大锤④，但资源异质 ⇒ 着色变装箱
```

## 大锤④：自动微分 = 线性映射转置 = 反向数据流

**这是第二样真正新的东西——但它的内核全是老锤子。**

### 骨架

给定程序 `f : ℝⁿ → ℝᵐ`，AD 生成两种导数程序：

```
前向模式（JVP，pushforward）：   jvp_f : (x, δx) ↦ (f(x), ∂f(x)·δx)
反向模式（VJP，pullback）：      vjp_f : (x, δy) ↦ (f(x), δyᵀ·∂f(x))
```

**关键结构性事实**（JAX 的设计把它做成了显式的三步）：

```
① linearize：把 f 在 x 处线性化，得到一个线性映射 L = ∂f(x)
              —— 这是一次偏求值！（把 x 烧进去，得到只依赖 δx 的线性程序）
② transpose：把线性程序 L 转置，得到 Lᵀ
              —— 这是纯语法变换：把 DAG 的每条边反向，每个线性算子换成其转置
③ 组合：      vjp = transpose(linearize(f))
```

**转置规则表**（这是全部内容）：

| 前向线性算子                       | 转置                                    |
| ---------------------------- | ------------------------------------- |
| `y = A·x`（A 常量）              | `x̄ = Aᵀ·ȳ`                           |
| `z = x + y`（加法 / fan-in）     | `x̄ = z̄`, `ȳ = z̄`（**复制 / fan-out**） |
| `y = x; z = x`（复制 / fan-out） | `x̄ = ȳ + z̄`（**加法 / fan-in**）        |
| `y = broadcast(x)`           | `x̄ = sum(ȳ)`                         |
| `y = sum(x)`                 | `x̄ = broadcast(ȳ)`                   |
| `y = x[i]`（gather）           | `x̄[i] += ȳ`（scatter-add）             |
| `y = reshape/transpose(x)`   | 逆 reshape/transpose                   |

> **注意"加法 ↔ 复制"这一对**——它是整个 AD 的核心，也是"转置就是反向数据流"最直观的体现：
> 
> ```
> 前向：一个值被用了 k 次（fan-out）
> 反向：k 个梯度贡献汇合到一处（fan-in，求和）
> ```
> 
> **这与第三轮 §D 的"综合属性 vs 继承属性"、以及数据流分析的"正向 vs 反向"是同一个对偶。** 具体地：
> 
> |      | 正向数据流         | 反向数据流          | AD         |
> | ---- | ------------- | -------------- | ---------- |
> | 信息流向 | def → use     | use → def      | 反向模式 AD    |
> | 汇合点  | 控制流 join（多前驱） | 控制流 split（多后继） | **多用户处求和** |
> | 汇合算子 | `⊔`           | `⊔`            | **`+`**    |
> 
> **反向模式 AD 就是"以加法为汇合算子的反向数据流分析"**，只不过它不是求不动点，而是（因为 DAG 无环）**一遍逆拓扑序折叠**（§D）。

### 钉子表

| 实现                             | 层次                                      | 手法                        |
| ------------------------------ | --------------------------------------- | ------------------------- |
| **PyTorch autograd**           | 运行时录带（tape）                             | 动态构造反向 DAG，反向执行           |
| **JAX**                        | 变换（`jvp`/`vjp`/`linearize`/`transpose`） | **显式三步分解**；`jaxpr` 上的程序变换 |
| **Zygote / Diffractor**（Julia） | 源到源（source-to-source）                   | 在 IR 上做变换                 |
| **Enzyme**                     | **LLVM IR 上的 AD pass**                  | **AD 作为一个编译器 pass**，语言无关  |
| **Tapenade / ADIC**（科学计算）      | Fortran/C 源到源                           | AD 领域的老前辈                 |
| **Dex**                        | 索引化的函数式语言                               | AD 与 Einsum 统一            |

> **Enzyme 值得强调**：它证明 **AD 是一个标准的编译器 pass**，可以放在 LLVM IR 上，与其他优化交错。更重要的是它的经验发现：**先优化再微分 ≫ 先微分再优化**——因为优化后的代码 AD 起来更简洁。**这又是 phase ordering 问题**，且答案与后端一致（"规范化要早做"）。

### 深层洞察：检查点 = 溢出 vs 重算

反向模式 AD 的根本问题：**反向需要用到前向的中间值**。

```
前向：  x₀ → x₁ → x₂ → … → xₙ
反向：  x̄ₙ → x̄ₙ₋₁ → … → x̄₀      每一步都需要对应的 xᵢ

⇒ 全存：内存 O(n)     计算 O(n)      —— 训练大模型时内存爆炸
⇒ 全不存：反向每步都从 x₀ 重算  内存 O(1)  计算 O(n²)  —— 太慢
⇒ 检查点：存一部分，其余重算
```

| 策略                  | 内存         | 额外计算         | 来源                              |
| ------------------- | ---------- | ------------ | ------------------------------- |
| 全存                  | `O(n)`     | 0            | 朴素                              |
| **均匀分段（√n 段）**      | `O(√n)`    | 1× 额外前向      | Chen et al. 2016                |
| **二项式检查点（revolve）** | `O(log n)` | `O(n log n)` | **Griewank 1992**，给定检查点数下**最优** |
| **ILP 最优调度**        | 任意预算       | 最优           | **Checkmate**（Jain et al. 2020） |
| 选择性重算               | 按算子代价加权    | 启发式          | 工业实现（`selective_checkpoint`）    |

> **这与寄存器分配的溢出决策完全同构，且对应关系精确到每一项**：
> 
> | 寄存器分配                 | 梯度检查点                                           |
> | --------------------- | ----------------------------------------------- |
> | 寄存器数 `k`              | 显存预算                                            |
> | 值的活跃区间                | 激活值从前向产生到反向使用的区间（**极长！**跨整个网络）                  |
> | **溢出**（spill 到栈）      | 存到 HBM / offload 到 CPU                          |
> | **重物化**（remat，重算而非溢出） | **重算激活值**                                       |
> | 溢出代价模型（循环深度加权）        | 重算代价（该段的 FLOPs）                                 |
> | 溢出位置选择 NP-hard        | 检查点选择：链上可 DP 最优；一般 DAG NP-hard ⇒ ILP（Checkmate） |
> | Briggs：宁可重算常量也不溢出     | 宁可重算 element-wise 也不存                           |
> 
> **两条注解**：
> 
> 1. **为什么 DL 里重算这么划算？** 因为激活值的活跃区间**极长**（跨整个前向+反向），而重算代价往往只是一两个 element-wise 算子——正是"活跃区间长 + 重算便宜"这个组合让重物化压倒溢出。这在标量编译器里是罕见情形（常量、地址计算），在 DL 里是**常态**。
> 2. **链结构给了我们最优解。** 一个前馈网络的激活值依赖是一条**链**，所以 Griewank 的 revolve 能给出最优解（链上 DP）。而一般计算图（残差、多分支）不是链 ⇒ 回到 NP-hard ⇒ ILP。**这又是"受限结构上最优、一般结构上 NP-hard"的老剧本**（第三轮 §4.3）。

> **洞察二：AD 与融合互相冲突 —— 一个新的 phase ordering 实例。**
> 
> ```
> 融合把多个算子合并成一个 kernel ⇒ 中间值不落盘
> 但反向可能需要那些中间值 ⇒ 融合迫使反向重算它们
> ⇒ "融合" 和 "为反向保存中间值" 是拮抗的
> ```
> 
> 这与后端"CSE 减少计算但延长活跃区间可能导致溢出"是完全同一类张力。而工业解法也一样：**联合考虑**（Inductor 的融合决策会考虑反向需求）或**分层决策 + 迭代**。

### 连线

```
transpose = 边反向 + 加法↔复制对偶 → 反向数据流分析（后端主锤）
但 DAG 无环 ⇒ 一遍逆拓扑折叠，不需迭代（§D.3）
linearize = 偏求值（把 x 烧进去）→ §C
检查点 = 溢出 vs 重算 → 后端大锤④，因算力/带宽比而反转
链上 revolve 最优，DAG 上 ILP → 受限结构最优的老剧本
AD ⊗ 融合 → phase ordering 的新实例
Enzyme：先优化再微分 → 规范化要早做
```

## 大锤⑤：图重写、等价饱和与"部分等价"

### 骨架

老锤子：**模式匹配 + 重写到不动点**（第三轮后端锤子③），只是这里的"项"是张量算子。

```
张量代数的重写规则：
  matmul(A, B)ᵀ           → matmul(Bᵀ, Aᵀ)
  concat(matmul(A,B₁), matmul(A,B₂)) → matmul(A, concat(B₁,B₂))    ← 批处理合并
  conv(x, W) + b          → fused_conv_bias(x, W, b)
  conv ∘ batchnorm        → conv（折叠 BN 到权重）★ 推理时的经典
  matmul(A, B) ∘ relu     → 融合
  transpose ∘ transpose   → identity
  reshape ∘ reshape       → reshape
  softmax(x + c)          → softmax(x)                             ← 数值等价
  sum(A, axis) ∘ mul      → 重结合以减少中间量
```

### 三代做法

| 代               | 做法                           | 代表                                               | 问题                        |
| --------------- | ---------------------------- | ------------------------------------------------ | ------------------------- |
| **人工规则 + 贪心重写** | 手写模式，顺序应用                    | XLA `algebraic_simplifier`、ONNX Runtime、TensorRT | **phase ordering**；规则库难维护 |
| **自动发现规则 + 验证** | 从算子规格自动枚举候选替换，用随机测试 + 形式验证筛选 | **TASO**（Jia et al. 2019）                        | 规则集仍受算子集限制                |
| **等价饱和**        | 不删除，只加等价关系，最后按代价提取           | **TENSAT**（ILP 提取）、egg 上的实现                      | 可能不饱和；提取需 ILP             |
| **部分等价变换**      | ★ **允许不等价的变换 + 插入补偿**        | **PET**（Wang et al. 2021）                        | 需要精确的"差异区域"分析             |

### 深层洞察

> **洞察一：TASO 是"超优化"在张量层的完整重现。**
> 
> ```
> Souper（标量）：枚举短指令序列 → SMT 验证等价 → 生成 peephole 规则
> TASO（张量）：  枚举小算子图  → 随机测试筛选 → 形式验证算子属性 → 生成图替换规则
> ```
> 
> 逐项对应。而 **TENSAT = TASO 的规则 + Equality Saturation**，正好对应"Souper 的规则 + egg"。
> 
> **提取阶段的差异值得注意**：标量 e-graph 提取常可用自底向上 DP（代价可加）；张量 e-graph **必须用 ILP**，因为**代价不可加**——两个算子能否融合、共享的中间张量算不算一次搬运，都依赖全局选择。**这是第三轮 §4.3 "共享破坏最优子结构" 的又一次出现**，只是这次共享的是内存流量而非计算。

> **洞察二：PET 的"部分等价变换"是本轮唯一在方法论上真正新颖的东西。**
> 
> ```
> 传统重写：  必须 ∀ 输入，old(x) = new(x)
>            ⇒ 很多高效的变换被排除（因为在边界/padding 处不等价）
> 
> PET：      允许 new(x) ≠ old(x)，但要求
>            ① 不等价只发生在一个可精确刻画的小区域（如边界）
>            ② 能生成一个便宜的"补偿 kernel"修正该区域
>            ⇒ 总代价 = 高效但错的主体 + 便宜的修正 < 正确但慢的原版
> ```
> 
> **为什么这在张量代数里可行而在标量代码里不可行？**
> 
> ```
> 标量：程序的"输出"是一个值，错了就是错了，无法"局部修正"
> 张量：程序的输出是一个大数组，"哪些元素错了"可以用仿射集合精确描述
>       ⇒ 错误区域可枚举、可修正（仿射表示的又一次回报）
> ```
> 
> **这条洞察的推广价值**：它说明"正确性"未必是全有全无的。只要
> 
> ```
> ① 不正确的部分可以被精确定位（需要一个足够强的表示——这里是多面体）
> ② 修正的代价远小于收益
> ```
> 
> 就可以把"近似正确 + 补偿"作为一个合法的优化手段。
> 
> **这与硬件/系统里的同一模式呼应**：投机执行（猜错就回滚）、乐观并发（冲突就重试）、纠错码（错了就纠）。第三轮的"乐观假设 + 可检测失败 + 昂贵退路"三段结构在这里变成了 **"不精确主体 + 可定位误差 + 便宜补偿"**——一个新变体，因为它不"回滚"，而是"打补丁"。

### 连线

```
图重写到不动点 → 第三轮后端锤子③
TASO → Souper/超优化的张量版
TENSAT → egg 的张量版；提取需 ILP（共享 ⇒ 代价不可加）
PET → ★ 新方法论：等价 → 可定位误差 + 补偿
     依赖仿射表示来"精确刻画错误区域"（主锤的回报）
```

## 大锤⑥：数值松弛 —— 等价被容差替代

**这是第三样真正新的东西，也是最麻烾的一样：它打破了第三轮 §H（模拟关系）这把正确性万能锤。**

### 问题

```
标量编译器：  变换正确 ⟺ ∃ 模拟关系（位精确等价，或定义好的细化关系）
             ⇒ 可以形式验证（CompCert、Alive2）

DL 编译器：   浮点加法不结合！  (a+b)+c ≠ a+(b+c)
             ⇒ 任何改变归约顺序的变换（分块、并行归约、向量化、切分）
               都会改变数值结果
             ⇒ 位精确等价是不可能达到的目标
             ⇒ 正确性只能定义为 "‖new(x) − old(x)‖ ≤ ε"
```

**而 `ε` 是什么，没有人能说清楚。**

### 后果一览

| 现象                  | 原因                       | 后果                             |
| ------------------- | ------------------------ | ------------------------------ |
| 换 tile 大小改变结果       | 归约顺序变了                   | **调优会改变数值** ⇒ 调优前后的模型输出不同      |
| 多 GPU 训练不可复现        | `atomicAdd` 顺序不确定        | 复现实验需要 `deterministic` 开关（且更慢） |
| 换硬件改变结果             | TF32 / bf16 累加器 / FMA 与否 | "模型在 A100 上能收敛，在 H100 上 NaN"   |
| 融合改变结果              | 中间量不落盘 ⇒ 保留了更高精度         | **融合后往往比不融合更准**（意外的好处）         |
| 混合精度需要 loss scaling | fp16 梯度下溢                | 编译器/框架必须介入数值范围管理               |
| 量化需要校准              | int8 需要 scale/zero-point | 需要**数据集**才能编译 ⇒ 编译依赖运行时信息      |

> **注意最后一行**：**量化让编译器依赖数据分布。** 这是 PGO 的极端版本——不只是分支频率，而是**张量的数值分布**成了编译输入。SmoothQuant、GPTQ、AWQ 本质上都是"用校准数据决定编译期常量（scale）"，即 **§C 偏求值：把数据分布当作 static 输入**。

### 深层洞察

> **洞察一：正确性从"等价关系"退化为"带 ε 的偏序"，导致三个万能锤失效。**
> 
> | 锤子                        | 在 DL 里怎么失效的                                               |
> | ------------------------- | --------------------------------------------------------- |
> | **§H 模拟关系 / 形式验证**        | 无法定义位精确的关系 ⇒ CompCert 式的端到端验证不可行                          |
> | **§E hash-consing / GVN** | "两个表达式相等"变成"数值上接近"⇒ 不能安全地合并（合并会改变精度）                      |
> | **§A 合一 / 等价类**           | 等价关系的传递性在容差下**不成立**（`a≈b, b≈c` 不推出 `a≈c`）⇒ Union-Find 不可用 |
> 
> **"容差不传递"是最要命的一条**：等价类机制的整个数学基础（等价关系）不成立了。所以 e-graph 用在张量代数上时，规则必须是**严格代数等价**的（`transpose∘transpose = id` ✔），而**数值上"差不多"的重写不能进 e-graph**（否则会通过传递性累积出任意大的误差）。
> 
> 这解释了一个实践现象：**DL 编译器的重写规则被分为两类**，且必须分开管理：
> 
> ```
> 严格等价规则：可自由重写、可进 e-graph、可无限组合
>              （reshape 合并、transpose 消除、代数恒等式）
> 数值近似规则：必须显式开关（--fast-math 类）、需要限次、需要端到端验证
>              （归约重结合、精度降级、算子替换如 gelu→gelu_approx）
> ```

> **洞察二：替代品是"差分测试 + 分层容差"，本质上是工程妥协。**
> 
> ```
> 参考实现（fp64 或 numpy）
>      ↓ 逐算子比对，容差按算子类型/规模设定
> 单算子测试（allclose with rtol/atol）
>      ↓
> 子图测试
>      ↓
> 端到端测试：训练能否收敛？下游任务指标是否退化？   ← 最终判据，但反馈周期 = 天
> ```
> 
> 这正是第三轮 §H 提到的"差分/模糊测试是模拟关系的工程近似版"——但在 DL 里它**不是近似，而是唯一可用的手段**。
> 
> **而这条链的最后一环（端到端指标）反馈周期是天级**，这是 DL 编译器 bug 特别难查的根本原因：**失败信号存在，但延迟极大。** 用第三轮的话说：**这是一个"可检测但检测代价极高"的失败信号**——比"没有信号"好，但差得不多。

> **洞察三：可复现性与性能的权衡，是一个被系统性低估的设计维度。**
> 
> ```
> 确定性归约（固定顺序）：慢，但可复现
> 非确定性归约（atomic）：快，不可复现
> ```
> 
> 大多数 DL 框架默认选后者，并提供 `deterministic=True` 开关。**这与编译器的 `-ffast-math` 是同一个决策，但影响面大得多**——因为 DL 的"结果"是要被科学论文引用的数字。
> 
> 一个务实的建议：**把"数值行为"当作和"性能"并列的一等编译目标**，在调优的目标函数里显式包含它（例如：在给定误差预算下最小化时间），而不是事后发现问题。目前几乎没有编译器这样做。

### 连线

```
容差不传递 → 打破 §A/§E 的等价类机制（必须区分严格/近似规则）
无位精确关系 → 打破 §H（形式验证不可用），退化为差分测试
量化校准 → §C 偏求值：数据分布作为 static 输入（PGO 的极端版）
可复现性 vs 性能 → -ffast-math 的同一决策，但后果严重得多
```

## 大锤⑦：集合通信代数 + 流水线 = 模调度

### 骨架

分布式并行**在编译器里**（而非运行时库里）解决，因为它需要全局的图信息。

**并行维度的正交分解**（这是 Alpa/GSPMD 的核心框架）：

| 并行方式              | 切什么            | 通信                                  | 对应的循环变换                            |
| ----------------- | -------------- | ----------------------------------- | ---------------------------------- |
| **数据并行**（DP）      | batch 维        | 梯度 `all-reduce`                     | 沿 batch 维分块 + 并行                   |
| **张量/算子内并行**（TP）  | 权重的某个维         | `all-gather` / `reduce-scatter`     | 沿 reduction 维或 output 维分块          |
| **序列并行**（SP）      | sequence 维     | `all-to-all` / ring                 | 沿 seq 维分块                          |
| **流水线/算子间并行**（PP） | **算子（图分割）**    | 相邻 stage `send/recv`                | **图级软件流水** ★                       |
| **专家并行**（EP）      | MoE 的 expert 维 | `all-to-all`                        | 沿 expert 维分块                       |
| **ZeRO / FSDP**   | 优化器状态、参数、梯度    | `all-gather` 参数、`reduce-scatter` 梯度 | 时间维上的"按需 gather + 用后丢弃" = **重物化！** |

> **ZeRO/FSDP 是重物化的又一次出现**：参数不全存在每张卡上，用到时 `all-gather` 过来，用完丢弃，反向再 gather 一次。
> 
> ```
> 溢出（spill）  → 参数放在别的卡上（跨网络存储）
> 重算（remat）  → 用时重新 gather（跨网络重取）
> ```
> 
> **"存储层级"被扩展到了网络。** 这印证了大锤②定律三的普适性：只要"获取/重取的代价 < 本地存储的代价"，就该重取。

### 深层洞察：流水线并行 = 模调度

> 这是本轮最强的一条跨领域连线。

```
GPipe / PipeDream 1F1B 的调度：
  把 batch 切成 m 个 micro-batch，网络切成 s 个 stage
  stage i 在时刻 t 处理某个 micro-batch 的前向或反向
  目标：最小化 bubble（空闲），受依赖约束（前向 i→i+1，反向 i+1→i）
```

**与软件流水（modulo scheduling）逐项对应**：

| 模调度（VLIW 循环软件流水）                 | 流水线并行                                             |
| -------------------------------- | ------------------------------------------------- |
| 循环迭代                             | **micro-batch**                                   |
| 功能单元 / 资源                        | **pipeline stage（设备）**                            |
| 迭代间依赖（recurrence）                | 前向/反向的跨 stage 依赖                                  |
| **启动间隔 II**（initiation interval） | 相邻 micro-batch 的注入间隔                              |
| prologue / epilogue              | **pipeline warmup / drain（bubble）**               |
| 资源约束下界 `ResMII`                  | 单 stage 的计算时间（负载均衡下界）                             |
| 递归约束下界 `RecMII`                  | 一个 micro-batch 走完前向+反向的延迟                         |
| 寄存器压力（跨迭代活跃的值）                   | **每个 stage 需缓存的激活值数量** ★                          |
| 模变量扩展（modulo variable expansion） | 每个 stage 保存多份 micro-batch 的激活                     |
| 迭代调度 IMS / SMS                   | GPipe / 1F1B / interleaved 1F1B / **zero-bubble** |

> **"寄存器压力 ↔ 激活值缓存数"这一行尤其重要**：
> 
> ```
> 1F1B 相对 GPipe 的核心改进 = 让每个 stage 只需缓存 O(stage 数) 份激活
>                              而非 O(micro-batch 数) 份
> ⇒ 这就是"减少跨迭代活跃值的数量"= 模调度里降低寄存器压力的标准手段
> ```
> 
> **所以 GPipe → 1F1B 的演进，就是"朴素软件流水 → 寄存器压力感知的软件流水"的重演。** 而 zero-bubble 流水线进一步把反向拆成"算权重梯度"和"算输入梯度"两半，以获得更细的调度粒度——这对应模调度里**把复杂指令拆分以获得更好的调度自由度**。

**Alpa 的分层求解方法也是老套路**：

```
inter-op（流水线阶段划分 + 设备分配）：  在链结构上 DP → 最优
intra-op（每个算子的切分方式选择）：      ILP（含通信代价的标注问题 = 大锤③）
⇒ 分层分解：外层 DP，内层 ILP
```

> **这与"调度 ⊗ 寄存器分配"的分层处理是同一个妥协**：联合最优是 NP-hard 且规模爆炸，于是分层——外层用可最优求解的结构（链上 DP），内层用求解器（ILP）。**注意外层能用 DP 恰恰因为流水线阶段构成一条链**（受限结构 ⇒ 多项式最优），又一次老剧本。

### 连线

```
sharding 传播 → 大锤③（标注传播）
切分规则 ← 主锤的 indexing_maps 自动导出
流水线并行 ≡ 模调度 → 后端大锤④（VLIW 冷知识变成核心技术）
1F1B ≡ 寄存器压力感知的软件流水
ZeRO/FSDP ≡ 重物化（存储层级扩展到网络）
Alpa 分层 ≡ 调度⊗分配的分层妥协；链上 DP 最优的老剧本
```

## 8. 动态形状：JIT + 守卫 + 去优化的第三次重现

前面所有锤子都假设**形状编译期已知**。这个假设是 DL 编译器高性能的根基（形状已知 ⇒ 完全展开、常量传播、精确代价模型），也是它最大的脆弱点。

```
形状静态已知  ⇒ 偏求值大丰收：循环边界是常量、tile 能整除、代价模型精确
形状动态变化  ⇒ 要么每个形状重编译（编译爆炸），要么放弃特化（性能崩塌）
```

**这正是第三轮"何时承诺"母题的第三次完整重现**：

|          | ANTLR 4 的 ALL(\*) | JIT / 投机优化      | **DL 编译器的动态形状**                                 |
| -------- | ----------------- | --------------- | ----------------------------------------------- |
| 静态方案的死穴  | 前看语言非正则           | Rice 定理         | **形状不可静态确定**（batch/seq 依赖输入）                    |
| 转向运行期获得  | 真实 token 串 + 真实栈  | 真实类型/值/频率       | **真实形状**                                        |
| 决策依据     | 眼前这串 token        | 观测到的类型          | **观测到的形状**                                      |
| **守卫**   | ——                | 类型检查            | **形状守卫**（`s0 == 128`、`s1 % 8 == 0`）             |
| **缓存**   | DFA 状态缓存          | 代码缓存 + IC       | **按形状 key 的 kernel 缓存**                         |
| **失败退路** | SLL 失败 → 完整 LL    | 守卫失败 → deopt    | **守卫失败 → 重编译 / graph break / fallback 到 eager** |
| **分层**   | SLL → LL          | Tier-0 → Tier-N | **静态形状特化码 → 符号形状通用码 → eager 执行**                |
| 病理       | 反复 SLL 失败         | 去优化风暴           | **重编译风暴**（每个新形状触发一次编译）                          |
| 缓解       | ——                | ——              | **形状分桶**（padding 到 8/16/32/…）= widening！        |

> **`torch.compile` 的架构完整对应这张表**：
> 
> ```
> Dynamo：  字节码级追踪 + 生成守卫集（含形状守卫）→ FX graph
>           = 偏求值（§C）+ 守卫（PIC/deopt）
> 符号形状：SymInt + 基于 sympy 的约束推理（`s0 ≥ 1`、`s0*s1 == 4096`）
>           = 整数线性约束求解（§A）
> `mark_dynamic` / `dynamic=True`：手动指定哪些维不特化
>           = 手动指定 widening 点！
> Graph break：  遇到无法追踪的 Python ⇒ 切图，退回 eager
>           = 可检测的失败 + 退路 ✔
> Inductor 缓存：按 (graph, 守卫, 形状) 缓存
>           = §E/§I 记忆化
> ```
> 
> **"`mark_dynamic` = 手动指定 widening 点"这条对应值得记住**：区间分析里，程序员/编译器要选在哪里 widen（否则不终止）；动态形状里，要选哪些维放弃特化（否则重编译爆炸）。**同一个动作，同一个理由（保证终止/有界），同一个代价（损失精度/性能）。**

**形状分桶（bucketing）** 是这里最实用的技巧，也是最纯粹的 widening：

```
观测形状：  seq_len ∈ {17, 23, 31, 45, 88, 130, ...}   ⇒ 每个都编译 = 爆炸
分桶：      pad 到 {32, 64, 128, 256, 512}             ⇒ 只编译 5 份
代价：      浪费 padding 部分的计算（精度换终止性）
```

对比区间分析：

```
区间 widening：[0,0] ∇ [0,1] = [0,+∞]         —— 跳到上界，保证终止
形状分桶：     17 → 32，  88 → 128            —— 跳到桶边界，保证编译次数有界
```

> **完全同一个动作。** 并且"桶该怎么选"的困难也一样：桶太粗浪费大，桶太细编译多——正如 widening 太激进损失精度，太保守不终止。而 §2.6 提到的"**阈值 widening**：候选边界取自程序中出现的常量"在这里对应"**桶边界取自硬件对齐要求（8/16/64）和观测分布**"。

## 9. 升降表：哪些锤子升了，哪些降了

这一节是本轮最有价值的产出：**DL 编译器不是一套新工具，而是对同一套工具的一次权重重排。** 读懂这张表，就能理解 DL 编译器为什么长这样。

### 降级的锤子

| 锤子                                  | 在标量编译器里  | 在 DL 编译器里 | 原因                                                                      |
| ----------------------------------- | -------- | --------- | ----------------------------------------------------------------------- |
| **格上不动点迭代**（后端主锤）                   | **核心**   | **边缘**    | **DAG 无环 ⇒ 单遍折叠即可**（§D.3 的最强实证）。仅剩：sharding/layout 传播（1~2 遍收敛）、动态形状约束求解 |
| **NFA→DFA / 解析**（前端主锤）              | 核心       | **几乎不存在** | "前端"就是 Python 追踪；没有语法歧义问题                                               |
| **模拟关系 / 形式验证**（§H）                 | 正确性的唯一手段 | **失效**    | 数值容差（大锤⑥）；退化为差分测试                                                       |
| **图着色寄存器分配**                        | 核心       | **被替换**   | 资源异质 ⇒ 条带装箱；且重物化压倒溢出                                                    |
| **等价类 / GVN / hash-consing**（§E、§A） | 核心       | **受限**    | 容差不传递 ⇒ 只能用严格代数等价规则                                                     |
| **CPS / 状态机化**（§B）                  | 重要       | **边缘**    | 没有复杂控制流可降级（有控制流的部分直接 graph break）                                       |
| **指向/别名分析**                         | 核心       | **边缘**    | 张量是值语义、无别名（除了显式 in-place / donated buffer）                              |
| **判定树 / 分派**（§G）                    | 核心       | 边缘        | 无多态分派；kernel 选择是查表                                                      |

### 升级的锤子

| 锤子                   | 在标量编译器里     | 在 DL 编译器里          | 原因                                   |
| -------------------- | ----------- | ------------------ | ------------------------------------ |
| **多面体/仿射模型**（后端大锤⑤）  | 边缘（只适用仿射程序） | **中心（主锤）**         | DL 程序**天生**全是仿射循环嵌套——"只适用仿射"的限制不再是限制 |
| **代价模型 + 搜索**（后端大锤⑥） | 最后手段        | **主力（大锤①）**        | 硬件不可解析建模；调优成本可被摊销（一个 kernel 用亿万次）    |
| **偏求值 / 特化**（§C）     | 一批优化之一      | **架构级**            | 形状/权重编译期已知 ⇒ 特化收益极大；追踪+守卫+缓存成为整个前端架构 |
| **最小割 / 标注问题**       | 岛屿（PRE）     | **大陆（大锤③）**        | layout/sharding/精度/存储空间全是它           |
| **模调度**（后端大锤④）       | VLIW 冷知识    | **千卡训练核心**         | 流水线并行 = 图级软件流水                       |
| **重物化**（RA 小技巧）      | 边角          | **一等公民（检查点/FSDP）** | 算力/带宽比极端化 ⇒ 重算压倒溢出                   |
| **ILP / 求解器归约**（§J）  | 学术玩具（编译太慢）  | **实用**             | 编译一次跑很久，可以承受分钟级 ILP                  |
| **记忆化 / 查询式**（§E、§I） | IDE 场景      | **必需**             | 调优缓存、编译缓存、远程缓存                       |
| **等价饱和 / E-graph**   | 前沿          | 前沿 + **需 ILP 提取**  | 代价不可加（融合与共享）                         |

### 一句话总结这张表

> **DL 编译器的"新"，90% 来自三个前提的改变**：
> 
> ```
> ① 程序无环         ⇒ 分析变简单（不动点降级），难度全在"选择"
> ② 目标变成带宽     ⇒ 融合/分块/重算升级，计算量优化降级
> ③ 语义变成容差     ⇒ 正确性工具失效，验证退回测试
> ```
> 
> **剩下 10% 是真新的：AD、集合通信、量化校准。** 而这三样的内核仍是老锤子（反向数据流、标注传播、偏求值）。

## 10. 三条根本局限（以及 FlashAttention 为什么找不出来）

每轮都要诚实列出锤子的失效域。DL 编译器的失效域格外重要，因为它解释了**为什么手写 kernel 仍然赢**。

### 局限一：调度空间不包含算法重构

> **这是最重要的一条。**

```
Halide 的前提：算法固定，只搜调度
⇒ 任何需要"改变算法"的优化，搜索器原理上找不到
```

**FlashAttention 是决定性的反例**：

```
朴素 attention:
    S = Q Kᵀ                        # 落盘 N×N 矩阵 —— 这是全部问题所在
    P = softmax(S)                  # 需要 S 的全局 max 和 sum ⇒ 必须完整物化 S
    O = P V

FlashAttention:
    分块遍历 K/V，用 online softmax 增量维护 (running_max, running_sum, running_O)
    每读入一块，就"重新缩放"已累积的 O：
        m_new = max(m_old, m_block)
        O = O · exp(m_old − m_new) + P_block · V_block · (...)
    ⇒ 从不物化 N×N 矩阵，内存 O(N)，算术强度大幅提升
```

**为什么调度搜索找不到它**：

```
① 融合被"规约屏障"阻断：softmax 需要全局 max/sum，看起来必须先完整算出 S
② 破除屏障需要一个数学恒等式（online softmax 的重缩放技巧），
   它不在任何调度原语的组合里 —— 它是一次算法替换，不是调度选择
③ 它还需要"反向时重算 S"（重物化），与"存 S"是不同的算法，不是不同的调度
```

> **用第三轮的语言精确定位这个局限**：
> 
> ```
> 调度搜索 = 在"调度空间"里搜索 ⇒ 空间由调度原语的组合定义
> FlashAttention 需要的 = 一条新的重写规则（online softmax）
> ⇒ 这是 e-graph 的"规则集完备性"问题，不是搜索强度问题
> ```
> 
> **而"规则集完备性"的解法是超优化（自动发现规则）**——但 TASO/Souper 式的枚举在张量代数里遇到组合爆炸，且 online softmax 这类"带补偿的增量算法"需要引入新的中间状态（running max/sum），远超"枚举小算子图"的能力。
> 
> **这是目前 DL 编译器与手写 kernel 之间最本质的差距，也是最值得研究的方向。**
> 
> 部分应对：
> 
> - **把规约算子的代数性质暴露给编译器**（结合律、可增量化、可重缩放）⇒ 让"流式化规约"成为一条可用的重写规则
> - **提供更高层的可组合原语**（Dex/Triton 的 `tl.reduce`、JAX 的 `associative_scan`）⇒ 让程序员表达算法，编译器搜调度
> - **让专家写微内核，编译器管外层**（当前工程最优解）

### 局限二：学习代价模型没有可检测的失败信号

```
真机测量：慢，但正确
学习模型：快，但预测错了不会报错
⇒ 泛化到新硬件/新算子/新形状时，你不知道它错了
```

> **这是第三轮"好的近似必须配可检测的失败信号"的直接违反。**
> 
> 可行的补救（目前少有实现）：
> 
> ```
> ① 让代价模型输出置信区间，低置信时强制实测       ← 提供信号
> ② 用屋顶线做上界检查：预测值超过理论上界 ⇒ 模型错了  ← 廉价的 sanity check
> ③ 保留 top-k 候选实测，而非信任 top-1              ← 用冗余换鲁棒
> ```
> 
> ②尤其便宜且有效：**屋顶线给出了一个物理上界，任何超过它的预测都是错的。** 这是罕见的"免费的失败信号"。

### 局限三：抽象层次一旦选定，就把一整类优化关在门外

```
太高（库调用）：       无法融合
太低（标量循环）：     丢失张量结构，无法用 MMA、无法做 layout 推理
"刚好"（tile 级）：    需要程序员承诺分块决策
```

> 这就是第三轮 §12 的通用诊断法在 DL 里的应用：
> **"当你在用分析把之前变换丢掉的信息猜回来时，说明归约做早了。"**
> 
> DL 编译器里的经典症状：
> 
> | 症状                 | 说明                                            | 现代解法                                    |
> | ------------------ | --------------------------------------------- | --------------------------------------- |
> | 从标量循环重新识别 GEMM     | 降到 scf/affine 后，为了用 tensor core 又要 raise 回矩阵乘 | **保留 `linalg.matmul` 这样的命名结构化算子**，别过早降级 |
> | 从展开的循环里识别 `reduce` | idiom recognition                             | 保留 `iterator_types = reduction`         |
> | 从 kernel 里反推融合边界   | 已经生成 kernel 后再想融合                             | 融合决策必须在图层做                              |
> | 从 fp32 图推断量化点      | 精度信息已丢失                                       | 量化标注要在图层携带                              |
> | 从单卡图推断切分           | 已经 lower 到单设备                                 | sharding 必须在图层传播（GSPMD 的做法）             |
> 
> **MLIR 的整套设计（多 dialect + 渐进降级 + transform dialect）就是对这条诊断法的制度化回应**：不预设"正确的抽象层"，而是让每类优化在它信息最完整的那一层做。

### 局限四（附）：编译时间

```
Ansor 搜一个网络：小时~天级
Alpa 的 ILP：      分钟级
动态形状重编译：   每个新形状一次
⇒ 在"改一行代码看效果"的开发循环里完全不可用
```

**这是"惰性 vs 激进"（第三轮 §9 主题三）在 DL 里最尖锐的形式**，也解释了为什么工业上主流是：

```
开发期：eager / 少量融合（编译 <1s）
上线前：完整调优（可以跑一晚）
上线后：缓存 + 分桶（避免重编译）
```

**三层策略，又是"便宜近似 → 昂贵精确"的老模式。**

## 11. 归并：仍然只有那五种机制

把四轮所有锤子放在一起，DL 编译器**没有增加第六种机制**：

### 机制 I：归纳结构上的计算（折叠 ⟷ 不动点）

```
DL 程序无环 ⇒ 几乎全是折叠：
    shape inference（一遍前向折叠）
    AD 的 transpose（一遍逆拓扑折叠）
    融合分析、内存活跃区间计算

仍需不动点的少数处：
    sharding / layout 传播（1~2 遍收敛）
    动态形状的符号约束求解
    图重写到不动点、e-graph rebuild
```

> **这是 §D.3 结论的决定性验证**：折叠与不动点是同一把锤子在"无环/有环"上的两种形态。**DL 编译器是"无环"这一侧的纯粹样本**，而它确实几乎不需要迭代。

### 机制 II：等价性管理

```
判定：  张量代数恒等式；TASO 的自动发现 + 验证
表示：  e-graph（TENSAT）；图规范化（canonicalization）
证明：  ★ 被容差破坏 ⇒ 退化为差分测试 + 分层容差
新增：  ★ PET 的"部分等价 + 补偿"——等价性的一个新变体
```

### 机制 III：表示变换

```
→ 仿射循环嵌套 / Einsum        消灭了：每个算子每个变换的独立实现
→ 结构化算子（indexing_maps）   消灭了：融合/分块/切分的 O(n²) 模式匹配
→ 调度作为一等对象              消灭了：合法性分析（by construction）
→ 多层 dialect（MLIR）          消灭了：过早的信息丢失
→ 反向图（AD transpose）        消灭了：手写梯度
```

### 机制 IV：特化与摊销

```
静态特化：形状/权重/量化 scale 烧进 kernel（Futamura 大丰收）
惰性记忆化：调优缓存、编译缓存、远程缓存
运行期特化：Dynamo 追踪 + 形状守卫 + graph break（= JIT + deopt）
有界化：★ 形状分桶 = widening（同一个动作，同一个理由）
```

### 机制 V：归约与分层

```
融合决策    → 图划分（NP-hard）→ 贪心/DP/ILP
标注问题    → 传播/最小割/ILP
调度选择    → 搜索
流水线      → 模调度
检查点      → 链上 DP / 一般图 ILP
分层：图层 → 算子层 → 循环层 → 向量/MMA 层（MLIR 渐进降级）
       inter-op DP ⊗ intra-op ILP（Alpa）
```

### 三条元原则（不变）

```
① 迭代到不动点。            —— 在 DL 里退化为"折叠一遍"，因为无环
② 换一个使问题变简单的表示。 —— 仿射表示 + 结构化算子，是 DL 编译器最大的杠杆
③ 决定何时承诺、何时丢弃信息，并为承诺错了准备可检测的退路。
                            —— 形状分桶、graph break、守卫、真机实测
                            —— 而 DL 里最大的问题恰恰是：★ 学习代价模型没有退路信号
```

## 收束

> **四轮下来，可以给出一个完整的结论。**
> 
> **前端的锤子是 NFA→DFA。后端的主锤是格上不动点迭代。而它们是同一把——子集构造就是幂集格上的最小不动点。**
> 
> **DL 编译器没有给这个体系添加第六种机制。** 它做的是一次残酷而清晰的**权重重排**，而重排的三个原因，恰好各自杀死了一把前三轮的核心锤子：
> 
> ```
> ① 程序是无环 DAG
>    ⇒ 不动点迭代退化为一遍折叠（§D.3 的最强实证）
>    ⇒ 分析变得容易，全部难度转移到"选择"上
>    ⇒ 于是 搜索（大锤⑥）从兜底升为主力
> 
> ② 目标函数从"算得少"变成"搬得少"
>    ⇒ 融合、分块、重物化 从边角升为核心
>    ⇒ 而"算力/带宽比"的极端化，让"重算 vs 存取"这个古老的溢出决策整体翻转
>    ⇒ 于是 梯度检查点、FSDP、多级 tiling 都成了寄存器分配的重演
> 
> ③ 语义从"位精确等价"变成"数值容差"
>    ⇒ 模拟关系（§H）失效，形式验证不可用，退回差分测试
>    ⇒ 等价类机制（§A/§E）受限，因为容差不传递
>    ⇒ 这是 DL 编译器唯一真正丢掉了一把锤子而没有补上的地方
> ```
> 
> **真正新的只有三样**：算术强度作为目标函数、自动微分作为程序变换、数值容差作为正确性标准。而前两样的内核仍是老锤子（屋顶线是代价模型，AD 是反向数据流 + 溢出决策）。
> 
> **三条元原则一字未改：**
> 
> **迭代到不动点。**（在 DL 里它退化为"折叠一遍"——而这恰好证明了它的正确性：环决定一切。）
> 
> **换一个使问题变简单的表示。**（仿射循环嵌套 + `indexing_maps`，是 DL 编译器最大的单一杠杆；它把 `O(n²)` 的算子对模式匹配变成 `O(1)` 的通用实现，正如 SSA 把到达定值分析变成 IR 里的一条边。）
> 
> **决定何时承诺、何时丢弃信息——并为承诺错了准备一条可检测的退路。**
> 这一条在 DL 里同时给出了最好和最坏的例子：
> 
> - **最好**：Dynamo 的 graph break、形状守卫、真机实测、屋顶线上界检查——都是清晰的失败信号。
> - **最坏**：**学习代价模型**。它快、它有效、它是现代 DL 编译器的基础设施——**而它猜错的时候，你什么也不会知道。**
> 
> 这与 PEG 的有序选择、贪心 peephole、上下文不敏感指向分析并列，构成同一份名单上的第四个名字。名单上这些技术的共同缺陷从来不是"不够精确"——
> 
> **而是它们失败的时候，你不知道。**

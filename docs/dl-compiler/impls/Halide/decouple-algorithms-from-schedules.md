
# Halide 的核心思想：算法与调度分离

## 1. 问题背景

在图像处理等高性能计算中，同一个算法可以有很多种实现方式，性能可能相差 **10 到 100 倍**。传统做法是手写优化代码，但这样做有几个问题：

- **算法逻辑被淹没**：分块、向量化、多线程等优化代码和计算逻辑交织在一起，难以阅读。
- **难以移植**：针对 x86 优化的代码，换到 ARM 或 GPU 上往往要重写。
- **难以探索**：想尝试另一种优化策略，就得大改代码，容易引入错误。

Halide 的解决方案是把程序拆成两个独立部分：

| 部分 | 回答的问题 | 特点 |
|------|-----------|------|
| **算法（Algorithm）** | 计算**什么** | 纯函数式描述，定义每个像素的值 |
| **调度（Schedule）** | **怎么**计算 | 计算顺序、存储位置、并行方式、向量化等 |

关键在于：**修改调度不会改变计算结果，只影响性能。**

---

## 2. 经典示例：3×3 均值模糊

### 算法部分

```cpp
#include "Halide.h"
using namespace Halide;

ImageParam input(UInt(16), 2);
Func blur_x("blur_x"), blur_y("blur_y");
Var x("x"), y("y"), xi("xi"), yi("yi");

// 算法：只描述数学关系
blur_x(x, y) = (input(x - 1, y) + input(x, y) + input(x + 1, y)) / 3;
blur_y(x, y) = (blur_x(x, y - 1) + blur_x(x, y) + blur_x(x, y + 1)) / 3;
```

这段代码里没有循环、没有内存分配、没有线程，只说明了每个像素等于什么。

### 调度部分

```cpp
// 调度：描述如何高效执行
blur_y.tile(x, y, xi, yi, 256, 32)   // 将输出分成 256×32 的块
      .vectorize(xi, 8)              // 内层用 SIMD，每次处理 8 个像素
      .parallel(y);                  // 块的行之间多线程并行

blur_x.compute_at(blur_y, x)         // 在每个块内按需计算 blur_x
      .vectorize(x, 8);
```

这几行调度的效果，相当于数百行手写的 SIMD 加多线程 C++ 代码。在 Halide 论文中，它的性能可以和专家手工优化的版本相当，甚至更好。

## 3. 调度的本质：三者之间的权衡

Halide 论文（Ragan-Kelley 等，PLDI 2013）指出，图像流水线的调度本质上是在三个目标之间权衡：

```
          并行性 (Parallelism)
               /\
              /  \
             /    \
            /______\
   局部性            冗余计算
  (Locality)      (Redundant Work)
```

以 `blur_x` 的计算位置为例：

| 策略 | 调度写法 | 局部性 | 冗余计算 | 并行性 |
|------|---------|--------|---------|--------|
| **内联**（默认） | 不写 | 好 | 多（每个点算 3 次） | 好 |
| **整体预先计算** | `blur_x.compute_root()` | 差（中间结果写回内存） | 无 | 好 |
| **按块计算** | `blur_x.compute_at(blur_y, x)` | 好（数据留在缓存） | 少（只有块边缘重复） | 好 |

没有一种策略在所有硬件和图像尺寸下都是最优的，所以需要灵活地尝试，而算法与调度分离正好让这种尝试变得很便宜。

## 4. 常用调度原语

**循环结构变换（针对单个函数内部）：**
- `split(x, xo, xi, factor)`：把一个循环拆成内外两层
- `reorder(...)`：交换循环嵌套顺序
- `tile(...)`：二维分块，相当于 split 加 reorder
- `fuse(...)`：合并循环

**执行方式：**
- `vectorize(x, n)`：SIMD 向量化
- `parallel(y)`：多线程并行
- `unroll(x, n)`：循环展开
- `gpu_tile(...)` / `gpu_blocks` / `gpu_threads`：映射到 GPU

**函数之间的关系（生产者与消费者）：**
- 默认：内联到消费者中
- `compute_root()`：在最外层一次性算完并存储
- `compute_at(f, var)`：在消费者 `f` 的某层循环内部计算
- `store_at(f, var)`：控制存储分配的位置，可与 `compute_at` 组合实现滑动窗口复用

## 5. 带来的好处

1. **代码清晰**：算法部分短小，接近数学公式，便于验证正确性。
2. **快速调优**：改一两行调度就能尝试新策略，结果保证不变。
3. **跨平台**：同一份算法可以配不同调度，分别生成 x86、ARM、GPU（CUDA、OpenCL、Metal）、Hexagon DSP 等后端代码。
4. **自动调度**：由于调度空间是形式化定义的，可以用搜索或机器学习自动寻找好的调度。例如 Mullapudi 2016 和 Adams 2019 等自动调度器。

---

## 6. 局限性

- **表达能力受限**：最适合规则的、类似 stencil 的稠密数组计算。不规则数据结构（如图、稀疏矩阵）或强数据依赖的控制流比较难表达。
- **归约需要特殊语法**：直方图、累加等操作要用 `RDom`（归约域）和更新定义（update definition）来写。
- **调度仍需专业知识**：手写好的调度需要理解缓存、SIMD 和并行等硬件知识，自动调度器也不总能达到专家水平。

---

## 7. 影响

这种"计算与调度分离"的思想影响深远，后来的很多系统都借鉴了它：

- **TVM**（深度学习编译器）直接采用了 Halide 风格的调度原语
- **TACO**（稀疏张量代数编译器）
- **Exo**、**Tiramisu** 等调度语言
- **MLIR**、**Triton** 等也吸收了相关理念


Halide 是由 MIT 与 Adobe 联合研发的图像处理领域特定语言（DSL），核心创新是**算法与执行调度严格分离**的编程模型。它不仅是计算摄影领域的工业级事实标准，也对整个编译器、高性能计算与 AI 编译领域产生了范式级的深远影响，具体体现在以下四个层面。

---

### 学术影响力：领域级奠基性工作

1. **顶会级权威认可** 2013 年发表于 PLDI 的创始论文，于 2023 年获得 **SIGPLAN PLDI 最具影响力论文奖**，是近十年编程语言与编译领域最受认可的标杆工作之一。后续成果陆续登陆 SIGGRAPH、POPL、CGO、Communications of the ACM 等顶会顶刊，是计算摄影、高性能 DSL 两个方向的核心参考文献。
2. **开创全新研究赛道** 首次将“算法-调度分离”的思想工程化落地，证明该模型可以在工业场景下达到甚至超越手写优化代码的性能，带动了一大批后续研究方向：基于搜索的自动调度、可微 Halide、向科学计算/稀疏计算的跨域扩展等。 它也成为所有数组/张量处理 DSL 研究的基准对比对象，后续同类工作均会以 Halide 作为性能与表达能力的对标基线。

---

### 工业界落地：大规模生产级验证

Halide 是极少数真正进入大规模工业生产的学术 DSL 项目，落地规模远超同类研究：

- **Google**：全面应用于 Pixel 系列手机的计算摄影管线、Google Photos 图像处理、YouTube 视频处理，是端侧计算摄影的核心技术底座之一。
- **Adobe**：深度集成于 Photoshop、Lightroom 的高性能图像处理管道，是其桌面端与移动端图像算法的核心实现方式。
- **高通**：用于骁龙平台的 DSP 图像处理加速，覆盖海量安卓旗舰机型。

公开数据显示，Halide 已部署到**数万台服务器、数亿部移动设备**，每日处理图像量级达数十亿张，是真实世界部署最广的编译器 DSL 之一。

---

### 技术范式影响：重塑高性能编译的设计思路

Halide 的影响力远超图像处理领域，其设计思想直接塑造了后续整个张量/数组编译领域的技术路线：

1. **直接孕育了 AI 编译框架 TVM** TVM 官方明确说明，其核心的**张量表达式（TE）+ 调度分离**模型完全继承自 Halide；底层的张量中间表示（TIR）、算术化简模块、代码降级流水线均直接借鉴或移植自 Halide 代码库。TVM 将 Halide 的范式从图像处理推广到了整个深度学习领域，成为 AI 编译的事实标准之一。
2. **深刻影响 MLIR 生态设计** LLVM MLIR 官方的 Linalg Dialect 设计文档中，专门辟出章节总结从 Halide 与 TVM 中吸取的经验与教训，包括规范化规则设计、声明式调度变换、面向数组的优化方法论；MLIR 的变换方言也大量参考了 Halide 的调度原语设计思路。
3. **降低高性能优化的技术门槛** 在 Halide 出现之前，循环变换、内存分层优化等 HPC 技术仅掌握在少数专家手中；Halide 通过声明式调度接口，将这套能力开放给普通开发者，推动了高性能编译技术的普及。

---

### 教学与行业标杆地位

- 是全球高校编译原理、高性能计算、计算摄影课程的经典教学案例，包括 MIT 6.172、斯坦福 CS149 等标杆课程均会系统讲解 Halide 的设计与实现。
- 定义了“图像处理 DSL”的行业标准，其调度原语、优化策略成为该领域的通用话语体系。

---

### 补充：核心边界

Halide 的影响力高度集中在**规则数组/图像处理**领域，对不规则计算、控制流密集的场景支持较弱，因此没有扩展为通用编程语言。但其核心的“算法-调度分离”思想，已经成为整个高性能编译领域的通用设计范式。

## 一、自我定位：你离这个岗位有多远

先对照岗位要求，评估自身差距：

| 岗位要求              | 硬门槛程度        | 说明                       |
| ----------------- | ------------ | ------------------------ |
| C/C++/Python      | ⭐⭐⭐ 必须       | C++ 是编译器开发主力语言           |
| **编译器原理 + 2 年经验** | ⭐⭐⭐⭐⭐ **核心** | 筛人的第一关                   |
| LLVM/GCC/Open64   | ⭐⭐⭐⭐⭐ **核心** | 现代 AI 编译器几乎都基于 LLVM/MLIR |
| 深度学习框架            | ⭐⭐⭐ 重要       | PyTorch/TensorFlow 的图优化  |
| 计算机体系结构           | ⭐⭐⭐⭐ 重要      | 后端代码生成必须懂硬件              |
| CUDA/OpenCL       | ⭐⭐⭐ 加分       | GPU/异构计算优化               |

> **关键判断**：如果你**从未接触过编译器开发**，"2 年以上编译器开发经验"这条会是最大障碍。招聘方通常将其作为硬性筛选。你需要**用项目和作品来证明能力**，弥补 title 上的空白。

## 二、按优先级补课（核心中的核心）

### 🎯 第 1 优先级：LLVM / MLIR（决定成败）

现代 AI 编译器（TVM、IREE、平头哥自研工具链等）**几乎都构建在 LLVM/MLIR 之上**。

**学习路径**：

```
1. 编译原理基础（龙书精读前 8 章）
   → 词法/语法分析、IR、优化、代码生成

2. LLVM 官方文档 + Kaleidoscope 教程
   → 亲手写一个玩具语言编译器前端

3. LLVM Pass 开发
   → 写几个自定义优化 Pass（死代码消除、循环优化）

4. MLIR 深入（AI 编译器的未来）
   → Dialect、Lowering、Toy Tutorial（官方）
```

**推荐资源**：

- 《Engineering a Compiler》（比龙书更实用）
- LLVM 官方 Kaleidoscope Tutorial
- MLIR 官方 Toy Tutorial
- 《深入理解 LLVM》系列博客

---

### 🎯 第 2 优先级：AI 编译器专项

这是岗位的「AI」属性所在，区别于传统编译器。

**必懂概念**：

| 主题                 | 关键点                                |
| ------------------ | ---------------------------------- |
| **计算图优化**          | 算子融合、常量折叠、图切分                      |
| **算子（Kernel）优化**   | Tiling、向量化、循环变换                    |
| **量化**             | INT8/FP16 混合精度                     |
| **内存规划**           | 内存复用、生命周期分析                        |
| **调度（Scheduling）** | Halide/TVM 的 compute/schedule 分离思想 |

**推荐深入项目**（选 1-2 个啃透源码）：

- **TVM**（Apache，最主流的 AI 编译器）
- **MLIR-based**：IREE、torch-mlir
- **平头哥自家**：了解 HHB、玄铁 RISC-V 工具链（面试直接相关）

---

### 🎯 第 3 优先级：计算机体系结构 + 后端

编译器后端要生成高效机器码，必须懂硬件。

**重点**：

- CPU：流水线、Cache、SIMD（SSE/AVX/NEON）
- GPU：SIMT、warp、shared memory
- **RISC-V**（平头哥玄铁核心是 RISC-V，务必了解 RVV 向量扩展）
- 指令调度、寄存器分配

> **针对平头哥的特别提示**：平头哥主打 **RISC-V + AI 加速**。如果你能展示对 **RISC-V 向量扩展（RVV）** 和自定义指令的理解，将是巨大的加分项。

## 三、利用 10 年经验的"降维打击"

不要只补短板，更要放大你的存量优势：

| 你的既有能力      | 如何转化为面试优势                    |
| ----------- | ---------------------------- |
| **工程化能力**   | 编译器是大型系统工程，你的架构设计、代码质量意识是稀缺的 |
| **性能优化经验**  | 若做过性能调优（缓存、并发、算法），直接对口"性能调优" |
| **系统底层经验**  | 若做过操作系统/驱动/嵌入式，体系结构这关能省很多力   |
| **问题解决能力**  | 编译器 debug 极其复杂，资深工程师的方法论是加分项 |
| **团队协作/带人** | 高级岗看重技术领导力，10 年经验天然契合        |

> **叙事策略**：把简历/面试重心放在「我用 X 年积累的**系统级思维和性能优化能力**，可快速迁移到编译器领域」，而非"我是编译器新手"。

## 四、实战准备：弥补"经验空白"的关键

**光学不够，必须有作品证明能力**：

### 1. 做一个能拿得出手的开源贡献

```
- 给 LLVM / TVM / MLIR 提交 PR（哪怕是小 bug fix / 文档）
- 这是最硬的"编译器开发经验"证明
```

### 2. 自己实现一个小项目

```
- 一个针对特定硬件的算子优化器
- 一个基于 MLIR 的简单 Dialect + Lowering
- 一个矩阵乘法从朴素到 SIMD 优化的完整过程（附 benchmark）
```

### 3. 写技术博客

```
- 记录你学 LLVM/MLIR 的过程
- 面试时可直接甩链接，证明学习能力和技术深度
```

## 五、面试可能考察的方向

| 类型          | 示例问题                       |
| ----------- | -------------------------- |
| **编译原理**    | SSA 是什么？为什么重要？如何做寄存器分配？    |
| **LLVM 实操** | LLVM IR 的结构？如何写一个 Pass？    |
| **优化算法**    | 循环展开/向量化怎么做？算子融合的收益和风险？    |
| **体系结构**    | Cache 局部性如何影响代码生成？SIMD 原理？ |
| **系统设计**    | 设计一个深度学习模型的编译流程            |
| **手写代码**    | C++ 实现某个数据结构/算法（可能考内存管理）   |

## 六、时间规划建议

**针对无编译器背景者**：

```
第 1-2 月：编译原理 + C++ 深度 + LLVM 入门
第 3-4 月：LLVM Pass 开发 + MLIR 基础
第 5-6 月：AI 编译器（TVM/MLIR）源码 + 体系结构
第 7 月起：开源贡献 + 个人项目 + 刷面试题
```

> 若你**已有编译器/系统底层背景**，周期可压缩到 **2-3 个月**。

## 七、诚恳建议与总结

### 三点务实建议

1. **先诚实评估**
   如果你完全没接触过编译器/系统底层，这条路很陡，但 10 年工程功底能显著加速。

2. **考虑"曲线救国"**
   可先投**编译器相关但门槛稍低**的岗位（如推理引擎、算子开发、性能优化工程师），积累 1-2 年再冲专家岗。

3. **主动联系内推**
   这类岗位纯投简历命中率低。找到平头哥内部人做内推，展示你的开源作品，效果远好于海投。

### 一句话总结

> 这个岗位的核心是 **LLVM/MLIR + AI 编译优化 + RISC-V 体系结构**。
> 
> 你的 10 年经验是「**加速器**」而非「**入场券**」——真正的入场券是**能证明编译器能力的实际作品**（开源 PR / 项目）。

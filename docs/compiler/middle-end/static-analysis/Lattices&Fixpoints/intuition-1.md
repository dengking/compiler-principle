# 直觉-1

在编译器优化（特别是数据流分析）中，**格（Lattice）是一张标注了信息精确度的“知识地图”，而不动点（Fixed Point）则是在地图上反复推理、直到所有结论都不再变化时到达的“稳定终点”**。

为了让学习者快速建立直觉，可以借助 **“侦探破案”** 的场景来理解这两个抽象概念。

> **约定说明**：本文采用龙书的写法：⊤ 在上，表示“尚无信息”；⊥ 在下，表示“不是常量”；合并用 meet（⊓）；迭代中的值自上而下移动。另一些教材把这张图上下翻转（用 join、自下而上），两种写法本质相同，文末附有对照。

---

### 1. Lattice（格）：知识精确度的层级地图

编译器在编译期并不运行程序，它只能像侦探一样，根据代码推断变量在某个程序点可能的取值。**Lattice 用来表示“我们对一个变量了解多少”的层级结构。**

以 **常量传播（Constant Propagation）** 为例，侦探（编译器）对变量 x 的结论分为三个层级：

```text
              ⊤  (UNDEF：尚无信息，还没有任何执行路径把消息带到这里)
        /   /   |   \   \
  ...  -1   0   1   2  ...   (常量：确定它就是某个具体常数)
        \   \   |   /   /
              ⊥  (NAC：Not A Constant，不是常量)
```

* **顶层 ⊤（乐观的起点）**：表示“目前还没有任何证人到场”。它**不是**“可能是任何值”，那是 ⊥ 的含义。分析开始时，编译器给**所有程序点**都标上 ⊤，意思是“暂时没有信息，先不对后续推理施加约束”。程序入口处的初值需要单独规定：未初始化的变量通常记为 ⊤，函数参数这类外部输入记为 ⊥。
* **中间层（具体常数）**：侦探读到赋值语句 `x = 5`，于是这条语句之后的程序点上，x 的结论就是 `5`。
* **底层 ⊥（保守端）**：表示“不是常量”。例如 `if` 分支里 `x = 5`，`else` 分支里 `x = 6`，两路汇合后证词冲突，编译器只能把结论定为 ⊥。⊥ 永远是**安全**的（“我不确定它是常量”不会出错），只是对优化没有帮助。
* **合并规则（meet）**：两条路径汇合时，按“证人对证词”的方式合并：

| 证人 A | 证人 B | 合并结论 |
| --- | --- | --- |
| ⊤ | v | v（一个证人没来，只听另一个） |
| c | c | c（证词一致） |
| c | d（c ≠ d） | ⊥（证词冲突） |
| ⊥ | 任意 | ⊥ |


* **单调性**：单调性是**每条语句的处理规则（transfer function）的性质**：输入越保守，输出不会反而更精确。

  在单调性的基础上，**只要从 ⊤ 出发**，**同一个程序点**的结论在一轮又一轮的迭代中**只会往下走，不会往回爬**。注意这里说的是“同一个程序点、不同轮次之间”。如果沿着代码往下读，结论当然可以变回常量：上一行 x 还是 ⊥，经过 `x = 5` 之后就是 5，因为**赋值会覆盖旧结论**。

### 2. Fixed Point（不动点）：情报传播的“稳态”

程序中的循环使控制流图（CFG）出现了**环**：循环头的结论依赖循环末尾，循环末尾的结论又依赖循环头，没法从头到尾一遍算完。所以编译器只能绕着环反复传递情报，直到结论稳定下来，也就是**到达 Fixed Point**。

用一段具体的代码来演示：

```c
x = 1;          // P0：这条语句之后
while (c) {     // H：循环头，H = meet(P0, P2)
    y = x + 1;  // P1：这条语句之后
    x = 2;      // P2：这条语句之后（循环体末尾）
}
```

把每个程序点想象成一个**传话筒**：根据上游传来的情报更新自己的笔记。每一轮依次更新 H、P1、P2。

| 轮次 | H.x | H.y | P1.x | P1.y | P2.x | P2.y |
|---|---|---|---|---|---|---|
| 初始 | ⊤ | ⊤ | ⊤ | ⊤ | ⊤ | ⊤ |
| 第 1 轮 | 1 | ⊤ | 1 | 2 | 2 | 2 |
| 第 2 轮 | **⊥** | 2 | ⊥ | ⊥ | **2** | ⊥ |
| 第 3 轮 | ⊥ | **⊥** | ⊥ | ⊥ | 2 | ⊥ |
| 第 4 轮 | ⊥ | ⊥ | ⊥ | ⊥ | 2 | ⊥ |

1. **第一轮传话**：大家手里都是空白笔记（⊤）。循环头只收到外部传来的 `x = 1`（另一条边还是 ⊤，不施加约束），于是记下 x = 1。循环体据此算出 y = 2，末尾的 `x = 2` 把 x 改写为 2。
2. **第二轮传话**：循环末尾的情报绕回了循环头。循环头发现，除了外部传来的 `x = 1`，循环末尾还传回来一个 `x = 2`。
3. **冲突合并（meet 操作）**：1 和 2 冲突，循环头把 x 的笔记改成 ⊥（不是常量）。这个 ⊥ 顺着循环往下传，使 P1 处的 x、y 都变成 ⊥。但传到 `x = 2` 时，**赋值语句覆盖了旧结论**，P2 处的 x 仍然是 2。所以 ⊥ **并没有感染循环体里的所有人**。
4. **第三轮传话**：P2 处 y 已经变为 ⊥，这条消息绕回循环头，循环头把 y 的笔记也改成了 ⊥。
5. **第四轮传话（达到不动点）**：情报又绕了一圈，大家对比新情报和自己的笔记，发现**没有任何一个人的笔记需要修改**。

这个 **“把当前所有结论代入再算一遍，得到的还是它们自己”** 的状态，就是 Fixed Point（不动点），即 F(S) = S。最终结论是：循环中 y 不是常量；x 在循环头不是常量，但在 `x = 2` 之后是常量 2。

**为什么要从 ⊤（乐观）出发？** 因为不动点可能不止一个。例如：

```c
x = 1;
while (c) { x = 2 - x; }   // 运行时 x 永远是 1
```

* 从 ⊤ 出发：循环头 = meet(1, ⊤) = 1，循环末尾 = 2 − 1 = 1；下一轮循环头 = meet(1, 1) = 1，稳定。**结论：x 是常量 1。**
* 如果从 ⊥ 出发：循环头 = meet(1, ⊥) = ⊥，循环末尾 = 2 − ⊥ = ⊥，同样稳定。结论：不知道。

两个状态都自洽，但从 ⊤ 出发得到的是**最大不动点**，它是所有不动点中最精确的。这就像侦探不预设立场，只在证据迫使时才放弃精确性。

### 总结：为什么这两个概念必须绑在一起？

只要 CFG 中有环，分析就必须迭代。（这与用户的代码会不会死循环**无关**：静态分析不执行代码，`while(1)` 并不会让分析器卡住。）编译器需要确信这个迭代一定会结束。Lattice、单调性和“从 ⊤ 出发”共同给出了一个**终止性保证**：

* **格的高度有限**：每个变量的结论从 ⊤ 到具体常数再到 ⊥，最多只能下降 2 级（这里说的是**格**的高度，格不是树）。整个程序的状态由“所有程序点 × 所有变量”构成，总高度是各部分之和，仍然有限。
* **只降不升**：在单调性和“从 ⊤ 出发”的前提下，每一轮迭代中，每个程序点的笔记要么不变，要么往下走，绝不会往上爬。一次可能**跨好几级**，例如 `x = read()` 会让结论从 ⊤ 直接变成 ⊥。
* **必然抵达 Fixed Point**：既然楼梯只有有限多级，而每次变化至少有一个笔记往下走，那么无论有多少层嵌套循环，编译器经过有限次迭代后**一定能停在一个稳定的台阶上**。循环越多、变量越多，所需的轮次也越多，但总有上限。

还需要分清三件不同的事：

| 问题 | 由什么保证 |
|---|---|
| **会不会停（终止）** | 格的高度有限 + 单调性。对区间分析这类高度无限的格，还需要 widening 强制终止 |
| **结果对不对（安全）** | 每条语句的处理规则和合并规则是否正确地刻画了程序语义 |
| **精度够不够（最优）** | 不动点可能不如“逐条路径分别计算再合并”（MOP）精确。例如 `if (c) {a=1; b=2;} else {a=2; b=1;} z = a + b;`，逐路径看 z 都是 3，但先合并 a、b 再计算会得到 ⊥ |

### 附：镜像写法对照

|           | 本文（龙书式） | 镜像写法   |
| --------- | ------- | ------ |
| 尚无信息（起点）  | ⊤       | ⊥      |
| 不是常量（保守端） | ⊥       | ⊤      |
| 合并操作      | meet ⊓  | join ⊔ |
| 值的移动方向    | 往下      | 往上     |
| 得到的结果     | 最大不动点   | 最小不动点  |

两列的迭代表格数字完全相同，只是符号互换。**不变的规律是：从“尚无信息”的一端出发，朝“不是常量”的一端移动。**

# 三地址码（Three-Address Code）技术文档

## 1. 概述

在编译器的整体架构中，前端将源程序解析为语法结构，后端则生成目标机器代码。连接二者的桥梁是**中间表示（Intermediate Representation, IR）**。**三地址码（Three-Address Code, TAC）** 正是最广泛使用的中间表示之一。

三地址码将源程序翻译为一系列**结构简单、形式统一**的指令序列，每条指令的复杂度受到严格限制。这种规范化的形式带来了两大优势：

- **便于代码优化**：简单指令的规整结构使**数据流分析**、**公共子表达式消除**等优化易于实施。
- **便于目标代码生成**：接近机器指令的抽象层次，使得从**三地址码**映射到实际**机器代码**相对直接。

三地址码由两大核心概念构成：

- **地址（Addresses）**：指令中操作数所引用的数据位置。
- **指令（Instructions）**：对地址执行的操作。

本文档系统介绍三地址码的形式定义、地址体系、指令类型及其实现方式。

---

## 2. "三地址"的形式与语义

### 2.1 命名由来

**三地址码**的名称来源于其指令中**地址的数量**。以最典型的赋值指令为例：

```
x = y op z
```

该指令包含三个地址位置和一个运算符：

| 位置  | 角色           | 说明        |
| --- | ------------ | --------- |
| `y` | 源操作数 1（arg1） | 参与运算的数据来源 |
| `z` | 源操作数 2（arg2） | 参与运算的数据来源 |
| `x` | 目标（result）   | 存放运算结果的位置 |

**核心约束**：每条指令**最多包含三个地址**、**一个运算符**。

### 2.2 形式约束的深远影响

这一约束是理解**三地址码**本质的关键。源程序中的表达式往往是**嵌套且复杂**的，而三地址码要求每条指令仅含单一运算符，因此复杂表达式必须被**分解**为一系列简单指令。分解过程中产生的中间结果需要临时存放之处——这直接催生了后文将讨论的**临时变量**。

**示例**：源代码 `x = a * b + 3` 无法在一条指令内完成，须分解为：

```
t1 = a  * b
t2 = t1 + 3
x  = t2
```

## 3. 地址（Addresses）

**地址**是**三地址码**指令中操作数的具体内容，即可以填入 `x`、`y`、`z` 位置的**数据来源**。一个地址可以是以下三种类型之一。

### 3.1 名字（Name）

**定义**：源程序中出现的变量名或标识符（如 `a`、`count`、`total`）。

**设计动机**：为便于阅读和书写，允许源程序名字直接作为地址出现在三地址码中。

**实现要点**：

- 编译器实现中，名字被替换为一个**指向其符号表条目（symbol-table entry）的指针**。
- 该名字的**所有相关信息**——类型、作用域、存储位置、大小等——集中保存在**符号表**中。
- 优势在于避免重复记录变量信息，并支持在任意引用点快速检索名字属性。

### 3.2 常量（Constant）

**定义**：程序中出现的字面值（如 `10`、`3.14`、`'A'`）。

**实现要点**：

- 编译器必须处理**多种不同类型**的常量与变量（整型、浮点型、字符型等）。
- 当不同类型的数据在同一表达式中混合运算时，需进行**类型转换（type conversion）**。
  - 例如：`int + float` 运算需先将整型操作数提升为浮点型。

### 3.3 编译器生成的临时变量（Compiler-Generated Temporary）

**定义**：编译器在翻译过程中自动创建的变量，用于保存中间计算结果（通常命名为 `t1`、`t2`、`t3`……）。

**命名策略**：

- 每当需要临时变量时，创建一个**全新且互不相同**的名字。
- 唯一命名策略在**优化编译器**中尤为重要：每个临时变量具备独立身份，便于**数据流分析**与值的追踪。

**寄存器分配阶段的合并**：

- 生成阶段使用大量不同临时名字，但在**寄存器分配（register allocation）**阶段，若多个临时变量的**生命周期不重叠**，可被合并至同一寄存器，从而节约**寄存器**资源。

## 4. 指令（Instructions）

指令是对地址执行的操作。三地址码的常见指令形式包括以下几类。

### 4.1 二元运算赋值

```
x = y op z
```

其中 `op` 为二元算术或逻辑运算符（如 `+`、`*`、`&&`）。

### 4.2 一元运算赋值

```
x = op y
```

其中 `op` 为一元运算符（如取负 `-`、逻辑非 `!`、类型转换等）。

### 4.3 复制指令

```
x = y
```

直接将 `y` 的值赋给 `x`。

### 4.4 无条件跳转

```
goto L
```

转移到带标号 `L` 的指令。

### 4.5 条件跳转

```
if x goto L
ifFalse x goto L
if x relop y goto L
```

根据条件决定是否跳转，`relop` 为关系运算符（如 `<`、`==`）。

### 4.6 过程调用与返回

```
param x       // 传递参数
call p, n     // 调用过程 p，n 个参数
y = call p, n // 带返回值的调用
return y      // 返回
```

### 4.7 数组引用

```
x = y[i]      // 读取数组元素
x[i] = y      // 写入数组元素
```

### 4.8 指针与地址操作

```
x = &y        // 取地址
x = *y        // 间接读取
*x = y        // 间接写入
```

## 5. 地址与指令的协同工作

三类地址填入指令的地址位置，共同完成从源程序到中间代码的翻译。

### 5.1 综合示例

翻译源代码 `(a + b) * (c + d)`：

```
t1 = a  + b      ← t1 保存第一个子表达式结果
t2 = c  + d      ← t2 保存第二个子表达式结果
t3 = t1 * t2     ← t3 保存最终乘积
```

各地址类型分析：

- `a`、`b`、`c`、`d`：**名字**（源程序变量）
- `t1`、`t2`、`t3`：**临时变量**（中间结果容器）

### 5.2 逻辑链条

```
          三地址码的形式约束
          （x = y op z，最多三个地址）
                    ↓
     复杂表达式必须拆解为简单指令序列
                    ↓
     指令的 x/y/z 位置需填入"地址"
                    ↓
   ┌──────────┬──────────┬──────────────┐
   │   名字    │   常量    │   临时变量     │
   │（源变量） │（字面值） │（中间结果容器）│
   └──────────┴──────────┴──────────────┘
```

这一链条揭示了三地址码的内在机理：**形式约束驱动指令分解，指令分解产生对地址（尤其是临时变量）的需求，三类地址共同支撑起整个指令序列。**

## 6. 三地址码的实现方式

### 6.1 面向对象实现

从面向对象视角，可将**地址**与**指令**建模为两个基类：

- 各类地址（名字、常量、临时变量）对应地址基类的**派生子类**。
- 各类指令对应指令基类的派生子类。

### 6.2 记录结构实现

三地址码也可采用**带地址字段的记录（record）结构**实现。常见方案有：

**四元式（Quadruples）**：包含 `op`、`arg1`、`arg2`、`result` 四个字段。

指令 `x = y op z` 对应：

```
(op, y, z, x)
  ↑   ↑  ↑  ↑
运算符 └──┴──┴── 三个地址字段
```

**三元式（Triples）**：省略显式的 `result` 字段，用指令自身的位置编号来引用其结果，从而减少存储开销。

两种记录形式的三个地址字段中存放的内容，正是**名字（符号表指针）、常量、或临时变量**三类地址之一。

---

## 7. 总结

| 维度       | 内容                                 |
| -------- | ---------------------------------- |
| **定位**   | 连接编译器前端与后端的中间表示                    |
| **命名由来** | 指令 `x = y op z` 中最多含 3 个地址位置       |
| **两大构成** | 地址（数据位置）+ 指令（操作）                   |
| **地址类型** | 名字（符号表指针）、常量（含类型转换）、临时变量（唯一命名、可合并） |
| **指令类型** | 运算赋值、复制、跳转、过程调用、数组与指针操作等           |
| **核心机理** | 形式约束驱动表达式分解，产生对地址的需求，二者相辅相成        |
| **实现方式** | 面向对象类层次；四元式 / 三元式记录结构              |

**核心结论**：三地址码通过"每条指令最多三个地址、一个运算符"的形式约束，将复杂的源程序表达式规范化为简单指令序列。地址提供操作数来源，指令定义操作行为，二者协同构成了一种既贴近机器、又便于分析优化的中间表示，为现代编译器的代码优化与目标代码生成奠定了坚实基础。

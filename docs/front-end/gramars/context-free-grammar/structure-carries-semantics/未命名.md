## 【替换】§3.2 项代数：所有能拼出来的模型

### 3.2 项代数：所有能拼出来的模型

把签名中的零件按插孔规矩随意拼装，所有可能拼出的模型构成**项集合（Set of Terms）** $T_\Sigma$，也就是所有**抽象语法树（Abstract Syntax Tree, AST）**。关于它，有三件事值得在直觉层面想清楚。

**（一）它是树，不是字符串。** 字符串 `2 + 3 * 4` 本身有**歧义（Ambiguity）**，既可以理解为 $(2+3)\times 4$，也可以理解为 $2+(3\times4)$。树没有这个问题，它的形状直接告诉你谁插在谁下面。

括号、**优先级（Precedence）**、空格属于**具体语法（Concrete Syntax）**，是写给人看的拼装**说明书**。**解析器（Parser）** 读完说明、拼好模型之后，说明书就可以扔掉了。`(2 + 3)` 里的那对括号在树中不对应任何节点，它的全部作用就是让 `+` 块插在 `×` 块下面。

**（二）自由生成：模型之间没有任何"视为相同"的约定。** 在项代数里：

- `Add(Lit 1, Lit 2)` 和 `Add(Lit 2, Lit 1)` 是**两个不同的模型**，尽管加法可交换；
- `Add(Lit 1, Lit 2)` 和 `Lit 3` 也是**不同的模型**，尽管它们算出来一样。

这就是 **自由生成（Freely Generated）** 的含义：除了"拼法不同就是不同的树"以外，没有任何额外的**等式（Equations）**。树只记录形状，对意思一无所知，因此不会擅自把两个形状认作一个。这一点在 §5.5 会成为初始性的关键，在 §9 又会被有意放宽。

**（三）它自己也是一个"代数"。** 所谓**代数（Algebra）**，就是一个 **载体集（Carrier Set）** 加上集合上的一些**运算（Operations）**。**项代数**的载体是**所有树**，**运算**则是：

- 加号运算：给定两棵树 $t_1, t_2$，返回新树 `Add(t1, t2)`，也就是把它们插到一个加号块下面；
- 乘号运算同理；
- 数字运算：给定整数 $n$，返回一个数字块。

这些运算什么都不算，只做**拼装**。项代数是一个"只会拼、不会算"的代数。

> **定义 3.2（项代数）**：由 $\Sigma$(signature) 中**运算符**构造的全体 **有限项（Finite Terms）** 组成集合 $T_\Sigma$。令每个运算符按语法方式作用：
> $$
> \sigma_{T_\Sigma}(t_1,\dots,t_n) = \sigma(t_1,\dots,t_n)
> $$
> 这样得到的代数称为**项代数（Term Algebra）**。当 $\mathrm{ar}(\sigma)=0$ 时，上式即 $\sigma_{T_\Sigma}() = \sigma$：零元运算返回那片单独的叶子，例如 $(\mathsf{lit}_3)_{T_\Sigma}$ 就是一块刻着 3 的数字块。

**例**：签名 $\{\mathtt{zero}:0,\ \mathtt{succ}:1\}$ 的项代数为 $\{\mathtt{zero},\ \mathtt{succ}(\mathtt{zero}),\ \mathtt{succ}(\mathtt{succ}(\mathtt{zero})),\dots\}$，同构于自然数 $\mathbb{N}$。

#### 读懂定义 3.2 中的等式

等式 $\sigma_{T_\Sigma}(t_1,\dots,t_n) = \sigma(t_1,\dots,t_n)$ 第一眼像同义反复，左右两边看起来一模一样。其实两边说的是**不同层面的东西**。

**左右两边各是什么。**

| | 左边 $\sigma_{T_\Sigma}(t_1,\dots,t_n)$ | 右边 $\sigma(t_1,\dots,t_n)$ |
|---|---|---|
| 性质 | 一次**函数调用** | 一个**数据对象**（一棵树） |
| 含义 | 代数 $T_\Sigma$ 对运算符 $\sigma$ 的**解释**，作用在 $t_1,\dots,t_n$ 上 | 以 $\sigma$ 为根、$t_1,\dots,t_n$ 为子树的**项** |
| 积木类比 | "手册里加号块那一页规定该怎么做" | "一个加号块，下面插着这几块积木" |

下标 $T_\Sigma$ 的用法与 §4.1 的定义 4.1 一致：任何 Σ-代数 $A$ 都要为每个 $\sigma$ 提供一个函数 $\sigma_A$。比如求值代数里，$\mathsf{add}_{\mathbb{Z}}(x,y)=x+y$。所以这个等式是在**规定项代数这本"手册"的内容**：运算 $\sigma_{T_\Sigma}$ 拿到 $n$ 棵树后什么也不算，只把它们插到一个 $\sigma$ 块下面，返回这棵新树。用引号写会更清楚：

$$
\sigma_{T_\Sigma}(t_1,\dots,t_n) = \text{“}\sigma(t_1,\dots,t_n)\text{”}
$$

右边是被"引用"的树，而不是被执行的计算。

**同一个 $\sigma$ 扮演两个角色。** 在签名里，$\sigma$ 只是一个带元数的**名字**，本身没有任何意思。在项代数里，这个名字被直接用作**构造子**，即把符号 $\sigma$ 放在子树顶上。所以这个等式可以读成："**在项代数中，运算符 $\sigma$ 的解释就是用符号 $\sigma$ 来拼装。**"

**一个具体对比。** 取 $t_1=\mathsf{lit}_2$，$t_2=\mathsf{mul}(\mathsf{lit}_3,\mathsf{lit}_4)$：

- 在项代数中，$\mathsf{add}_{T_\Sigma}(t_1,t_2)=\mathsf{add}(\mathsf{lit}_2,\ \mathsf{mul}(\mathsf{lit}_3,\mathsf{lit}_4))$，结果是 §2 画过的那棵树；
- 在 §4.1 的求值代数中，子项已被解读为 2 和 12，$\mathsf{add}_{\mathbb{Z}}(2,12)=14$，结果是一个整数。

同一个运算符，在不同代数里有不同解释。项代数的解释最"懒"：它只记录形状，不把形状压缩成任何结果。

**在代码里它长什么样。** 借用 §7.2 的记号，项代数就是这样一本手册，每一页都只是调用构造函数：

```python
term_alg = {
    "lit": lambda n:    Lit(n),     # lit_{T_Σ}(n)    = lit_n
    "add": lambda l, r: Add(l, r),  # add_{T_Σ}(l, r) = add(l, r)
    "mul": lambda l, r: Mul(l, r),  # mul_{T_Σ}(l, r) = mul(l, r)
}
```

在 Haskell 版里，这本手册打包起来就是 `In : ExprF Expr -> Expr`，也就是 §6.4 中的 $\mathrm{in}$。

**为什么要专门写出这个等式。** 它在后文承担了三项工作：

1. **让 $T_\Sigma$ 成为一个合格的 Σ-代数。** 定理 5.1 说"$T_\Sigma$ 是 Σ-代数范畴中的初始对象"。要谈这件事，$T_\Sigma$ 首先得**是**一个 Σ-代数，既要有载体（所有树），也要有每个运算符的解释。这个等式补上的正是后者。
2. **让同态条件变成递归定义。** 把 $A=T_\Sigma$ 代入同态条件（定义 4.2），利用本等式把左边的 $\sigma_{T_\Sigma}(\dots)$ 换成树 $\sigma(\dots)$，得到
   $$
   h(\sigma(t_1,\dots,t_n)) = \sigma_B(h(t_1),\dots,h(t_n))
   $$
   这正是 §5.3 中按树的结构做递归的那条式子，也就是 `fold` 的定义。**正因为项代数的运算"只拼装"，从它出发的同态才恰好等于"按手册从下往上解读"。**
3. **蕴含唯一拆分。** 运算的结果就是以 $\sigma$ 为根的树本身，所以不同运算符的结果不会相同（根部符号不同），同一运算符的结果相同当且仅当参数逐个相同。这就是上面（二）的"自由生成"，也是 §5.1 的"唯一拆分"。如果某个运算会做化简，比如把 $\mathsf{add}(\mathsf{lit}_1,\mathsf{lit}_2)$ 直接变成 $\mathsf{lit}_3$，这两点就会被破坏，项代数也就不再初始了（参见 §5.5 的思想实验）。

> **一句话**：定义 3.2 中的等式规定了项代数的运算，即在 $T_\Sigma$ 中"应用运算符 $\sigma$"的意思就是"造出以 $\sigma$ 为根的那棵树"。左边是解释，右边是语法；二者重合，说明项代数把语法本身当作了自己的"意思"。正因为它不做任何计算、不带任何偏见，每一本别的手册才都能以唯一方式接到它上面（§5）。

## 【替换】§5.3 形式陈述

### 5.3 形式陈述

> **定理 5.1（项代数的初始性）**：$T_\Sigma$ 是 $\mathbf{Alg}_\Sigma$ 的初始对象。即对任意 Σ-代数 $A$，存在唯一的 Σ-同态 $h_A: T_\Sigma\to A$。
>
> **证明**：由定义 4.2，同态条件是 $h_A(\sigma_{T_\Sigma}(t_1,\dots,t_n))=\sigma_A(h_A(t_1),\dots,h_A(t_n))$。由定义 3.2，$\sigma_{T_\Sigma}(t_1,\dots,t_n)$ 就是树 $\sigma(t_1,\dots,t_n)$，所以同态条件化为
> $$
> h_A(\sigma(t_1,\dots,t_n)) = \sigma_A(h_A(t_1),\dots,h_A(t_n))
> $$
> **存在性**：由唯一拆分，每个项 $t$ 都能唯一地写成 $\sigma(t_1,\dots,t_n)$。所以上式可以当作对项的结构递归定义，而且这个定义是良定义的，因为右边只用到 $t$ 的严格子项。
> **唯一性**：若 $g$ 也是同态，对 $t$ 做结构归纳可得 $g(t)=h_A(t)$，论证同 §5.2。∎

## 【替换】§6.4 中关于 $\mathrm{in}$ 的段落

记号 $(\!|\cdot|\!)$ 因形状被俗称为"香蕉括号（Banana Brackets）"（Meijer, Fokkinga & Paterson, 1991）。$\mathrm{in}:F(\mu F)\to\mu F$ 就是"把一层零件和若干棵子树拼成一棵新树"的拼装操作，也就是全体构造子打包而成的函数。换句话说，$\mathrm{in}$ 正是定义 3.2 中那组运算 $\sigma_{T_\Sigma}$ 打包后的样子，即 §3.2 的 `term_alg`。

用本文的语言说：**$\mu F$ 是所有能拼出的模型，$\mathrm{in}$ 是拼装，$(\!|\alpha|\!)$ 是按手册 $\alpha$ 进行的那唯一一种解读。**

项代数本身也是一本手册，就是 §3.2 的 `term_alg`。用它来解读，得到的正是原来那棵树：

```python
term_alg = {
    "lit": lambda n:    Lit(n),
    "add": lambda l, r: Add(l, r),
    "mul": lambda l, r: Mul(l, r),
}

assert fold(term_alg, e) == e   # 反射律 (| in |) = id 的直接演示
```

这本手册的每一页都只调用构造函数，即定义 3.2 中的 $\sigma_{T_\Sigma}(t_1,\dots,t_n)=\sigma(t_1,\dots,t_n)$。在所有手册中，它是唯一"不压缩任何信息"的一本。

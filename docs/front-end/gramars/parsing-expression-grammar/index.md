# PEG：解析表达式文法

**PEG** 是 **Parsing Expression Grammar（解析表达式文法）** 的缩写，由 Bryan Ford 在 2004 年的 POPL 论文 *Parsing Expression Grammars: A Recognition-Based Syntactic Foundation* 中提出。它是一种描述语法的形式体系，在形式上与 CFG（上下文无关文法）很像，但语义完全不同。

---

## 1. 核心思想：识别式而非生成式

- **CFG 是生成式的**：它描述"如何从开始符号推导出句子"，一个句子可能有多种推导方式，因此存在**二义性**。
- **PEG 是识别式的**：每条规则直接描述"解析器如何尝试匹配输入"，本质上就是一个带回溯的递归下降程序的形式化描述。

因此，**PEG 天生无二义性**：对任何输入，解析结果至多一个。

---

## 2. 语法与运算符

PEG 规则通常写作 `A <- e`。解析表达式 `e` 由以下运算符构成：

| 运算符 | 含义 |
|---|---|
| `'abc'` | 匹配字面量 |
| `[a-z]` | 字符类 |
| `.` | 任意单个字符 |
| `e1 e2` | 顺序：先匹配 e1，再匹配 e2 |
| `e1 / e2` | **有序选择**：先试 e1，成功即采用；失败才回溯并尝试 e2 |
| `e*` | 零次或多次（**贪婪**） |
| `e+` | 一次或多次（贪婪） |
| `e?` | 可选 |
| `&e` | **与谓词**：e 能匹配则成功，但不消耗输入 |
| `!e` | **非谓词**：e 不能匹配则成功，不消耗输入 |

前面 ETF 文法在 PEG 中的典型写法（用重复代替左递归）：

```
Expr   <- Term (('+' / '-') Term)*
Term   <- Factor (('*' / '/') Factor)*
Factor <- '(' Expr ')' / Id
Id     <- [a-zA-Z_] [a-zA-Z0-9_]*
```

---

## 3. 与 CFG 的关键差异

### 3.1 有序选择 `/` 与 CFG 的 `|` 不同

CFG 的 `|` 是无序的，所有备选地位相同；PEG 的 `/` 一旦某个分支成功就**提交**，不会再尝试后面的分支。

```
S <- ('a' / 'ab') !.
```

对输入 `ab`：`'a'` 先成功，接着 `!.`（要求到达输入末尾）失败，整个 S 失败。PEG 不会回头去尝试 `'ab'`。而对应的 CFG `S → a | ab` 显然能接受 `ab`。

所以在 PEG 中，**备选项的顺序有语义**，较长或较具体的分支通常要放在前面。

### 3.2 重复是贪婪且不回溯的

```
A <- 'a'* 'a'
```

这条规则**永远不会成功**：`'a'*` 吞掉所有的 `a`，后面的 `'a'` 无字符可匹配，而 `*` 不会"吐回"字符。这与正则表达式引擎的回溯行为不同。

### 3.3 谓词提供无限前瞻

`&e` 和 `!e` 可以检查任意长的后续输入而不消耗它。典型用途是区分关键字和标识符：

```
Keyword <- 'if' !IdChar      # 防止把 "iffy" 的前缀当成关键字 if
IdChar  <- [a-zA-Z0-9_]
```

### 3.4 天然解决二义性问题

经典的悬空 else（dangling else）问题：

```
Stmt <- 'if' Cond Stmt 'else' Stmt
      / 'if' Cond Stmt
      / Other
```

有序选择会优先尝试带 `else` 的分支，自然得到"else 与最近的 if 配对"的效果，无需额外的消歧规则。

### 3.5 无需独立词法分析器

PEG 直接在字符层面工作，词法和语法可以写在同一份文法中，称为**无扫描器解析**（scannerless parsing）。

## 4. 表达能力

PEG 与 CFG 的表达能力**互不包含关系尚未完全确定**：

- PEG 能识别某些**非上下文无关**语言。Ford 给出了识别 $\{a^n b^n c^n\}$ 的例子：
  ```
  S <- &(A 'c') 'a'+ B !.
  A <- 'a' A? 'b'
  B <- 'b' B? 'c'
  ```
  `&(A 'c')` 先用前瞻检查 a 与 b 数量相等，再由 `'a'+ B` 检查 b 与 c 数量相等。
- 是否**所有** CFL 都能被 PEG 识别，至今仍是一个**开放问题**。
- PEG 语言类在交、补运算下封闭（借助谓词）；但 PEG 的空性问题是不可判定的。

---

## 5. Packrat 解析

PEG 的朴素实现是带回溯的递归下降，最坏情况下是指数时间。Ford 在 2002 年提出的 **Packrat 解析**通过**记忆化**解决这个问题：

- 对每个（规则，输入位置）对，缓存其匹配结果；
- 每对至多计算一次，因此总时间是**线性**的 $O(n)$；
- 代价是空间开销为 $O(n \times |规则数|)$。

实践中很多实现只对部分规则做记忆化，以平衡时间和内存。

---

## 6. 左递归问题

这正是上一篇文章提到 PEG 的原因。由于 PEG 的执行方式与递归下降相同，左递归规则会导致无限递归：

```
Expr <- Expr '+' Term / Term     # 调用 Expr 时立即再次调用 Expr，不消耗输入
```

解决方案：

1. **改写为重复**：如第 2 节所示，用 `Term ('+' Term)*` 代替左递归，这是最常见的做法；
2. **种子增长**（seed growing，Warth 等人 2008）：先让左递归调用失败以获得一个"种子"结果，再反复迭代扩展，直到匹配不再变长。这使得 Packrat 解析器可以直接支持左递归，但间接左递归的处理要复杂得多。

| **cpp-peglib** | C++ | 头文件库 |
| **parsimonious** | Python | 轻量级 PEG 库 |

## 8. 优缺点总结

**优点**
- 无二义性，解析结果唯一且可预测；
- 与递归下降直接对应，易于手写和理解；
- 谓词提供强大的前瞻能力；
- 词法、语法可统一描述；
- Packrat 解析保证线性时间。

**缺点**
- 有序选择会**静默地**隐藏错误：备选顺序写错时，文法不会报冲突，只会悄悄地匹配失败或得到意外结果（而 LR 工具会报告移进-归约冲突）；
- 原生不支持左递归；
- Packrat 记忆化内存开销大；
- 错误报告相对困难，因为回溯使"真正的出错位置"不易确定（常用的启发式是报告到达的最远失败位置）。

---

**一句话概括**：PEG 是"把带回溯的递归下降解析器形式化"的一种文法体系，用有序选择消除二义性，用记忆化保证线性时间，但需要特别处理左递归，并要求编写者对备选顺序保持警惕。

# 正则表达式文法详解

```EBNF
alt     ::= concat ('|' concat)*
concat  ::= repeat*
repeat  ::= atom quant*
quant   ::= ('*' | '+' | '?' | '{' m (',' n?)? '}') ('?' | '+')?
atom    ::= literal | '.' | '^' | '$' | '(' alt ')' | '(?:' alt ')' | '(?>' alt ')'
          | '(?=' alt ')' | '(?!' alt ')' | '(?<=' alt ')' | '(?<!' alt ')'
          | class | escape
class   ::= '[' '^'? item+ ']'
escape  ::= '\d' | '\w' | '\s' | '\D' | '\W' | '\S' | '\b' | '\B' | '\1'..'\9' | '\' char
```

这是一份用 **EBNF(扩展巴科斯范式)** 写成的**正则表达式语法**。它描述的不是"正则能匹配什么字符串",而是"一个正则表达式本身应该怎么写",也就是正则引擎内部**解析器**所依据的语法规则。

---

## 一、先读懂记号(EBNF 元符号)

| 记号 | 含义 | 例子 |
|---|---|---|
| `::=` | "定义为" | `A ::= B` 表示 A 由 B 构成 |
| `'x'` | 字面字符(终结符) | `'|'` 就是竖线字符本身 |
| `X*` | X 重复 0 次或多次 | `repeat*` |
| `X?` | X 可选(0 或 1 次) | `'^'?` |
| `( … )` | 分组 | `('|' concat)*` |
| `A \| B` | A 或 B(选择) | `'*' \| '+'` |
| `'a'..'b'` | 字符范围 | `'\1'..'\9'` |

注意区分两种竖线:带引号的 `'|'` 是正则里的"或"字符,不带引号的 `|` 是文法的选择符号。

---

## 二、整体结构:四层优先级

前四条规则构成一个**由低到高的优先级阶梯**,这是理解整个文法的关键:

```
alt      (选择  |   )   ← 优先级最低,结合最松
  └─ concat  (连接  ab  )
       └─ repeat  (量词  a* )
            └─ atom  (原子)   ← 优先级最高,结合最紧
```

越靠下的规则结合越紧。所以 `ab|cd*` 的含义是 `(ab)|(c(d*))`,而不是 `a(b|c)d*`。这和算术表达式中"加法 < 乘法 < 括号"的分层写法完全同构:

| 算术 | 正则 |
|---|---|
| `expr ::= term ('+' term)*` | `alt ::= concat ('|' concat)*` |
| `term ::= factor ('*' factor)*` | `concat ::= repeat*` |
| `factor ::= num \| '(' expr ')'` | `atom ::= ... \| '(' alt ')'` |

## 三、逐条解释

### 1. `alt` —— 选择(Alternation)

```
alt ::= concat ('|' concat)*
```

由一个或多个 `concat` 构成,中间用 `|` 分隔。

- `cat|dog|bird` 是三个 concat:`cat`、`dog`、`bird`
- `abc` 只有一个 concat,没有 `|`

它是整个正则的**入口(起始符号)**,一个完整的正则表达式就是一个 `alt`。

### 2. `concat` —— 连接(Concatenation)

```
concat ::= repeat*
```

零个或多个 `repeat` 依次排列,表示"先匹配这个,再匹配那个"。连接没有显式运算符,**相邻即连接**。

使用 `*` 而不是 `+` 意味着 `concat` **可以为空**,因此以下写法都合法:

- `a|` 匹配 "a" 或空串
- `|b` 匹配空串或 "b"
- `()` 是空分组

### 3. `repeat` —— 重复

```
repeat ::= atom quant*
```

一个原子后面跟零个或多个量词,例如 `a`、`a*`、`(ab)+`、`\d{3}`。

注意这里写的是 `quant*`,允许**多个量词叠加**,如 `a*{2}`。不同引擎对此态度不同:Perl/PCRE 会对 `a**` 报错,有些引擎则会接受。这份文法比较宽松,具体限制留给语义检查阶段处理。

### 4. `quant` —— 量词(Quantifier)

```
quant ::= ('*' | '+' | '?' | '{' m (',' n?)? '}') ('?' | '+')?
```

分为两部分。

**第一部分:重复次数**

| 写法 | 含义 |
|---|---|
| `*` | 0 次或多次 |
| `+` | 1 次或多次 |
| `?` | 0 次或 1 次 |
| `{m}` | 恰好 m 次 |
| `{m,}` | 至少 m 次 |
| `{m,n}` | m 到 n 次 |

`'{' m (',' n?)? '}'` 的拆解如下:

- `m` 必须有
- `(',' n?)?` 整体可选:没有逗号就是 `{m}`
- 有逗号时 `n` 也可选:没有 n 就是 `{m,}`

按此文法,`{,n}` 不合法,因为 m 不能省略。

**第二部分:匹配模式后缀(可选)**
参见: [[regex-quantifier-match-mode-suffixes]] 

| 后缀 | 模式 | 例:`a+` 匹配 `"aaa"` |
|---|---|---|
| 无 | **贪婪**(greedy):尽量多吃,失败再回退 | 先吃 3 个,不行再吐 |
| `?` | **惰性/非贪婪**(lazy):尽量少吃 | 先吃 1 个,不行再多吃 |
| `+` | **占有**(possessive):尽量多吃,且**绝不回退** | 吃 3 个,失败就直接失败 |

例子:`".*"` 匹配 `"a" "b"` 时会吃到最后一个引号,得到 `"a" "b"`;而 `".*?"` 只得到 `"a"`。

### 5. `atom` —— 原子

```EBNF
atom ::= literal | '.' | '^' | '$'
       | '(' alt ')' | '(?:' alt ')' | '(?>' alt ')'
       | '(?=' alt ')' | '(?!' alt ')' | '(?<=' alt ')' | '(?<!' alt ')'
       | class | escape
```

原子是不可再分的最小匹配单元,分为以下几类。

**(a) 基本原子**

| 原子 | 含义 |
|---|---|
| `literal` | 普通字符,如 `a`、`7` |
| `.` | 任意字符(通常不含换行) |
| `^` | 行首/串首(零宽断言) |
| `$` | 行尾/串尾(零宽断言) |

**(b) 分组**,括号内部又是一个完整的 `alt`,这就是**递归**所在:

| 语法 | 名称 | 作用 |
|---|---|---|
| `(alt)` | 捕获组 | 分组,并记住匹配内容供 `\1` 等引用 |
| `(?:alt)` | 非捕获组 | 只分组,不记录,效率更高 |
| `(?>alt)` | 原子组/固化分组 | 组内一旦匹配成功就不再回溯 |

**(c) 环视断言(Lookaround)**,它们都是**零宽**的:只检查条件,不消耗字符。

| 语法 | 名称 | 含义 | 例子 |
|---|---|---|---|
| `(?=X)` | 正向先行 | 后面**是** X | `\d+(?=元)` 匹配"100元"中的"100" |
| `(?!X)` | 负向先行 | 后面**不是** X | `foo(?!bar)` |
| `(?<=X)` | 正向后行 | 前面**是** X | `(?<=\$)\d+` 匹配"$50"中的"50" |
| `(?<!X)` | 负向后行 | 前面**不是** X | `(?<!-)\d+` |

**(d) `class` 和 `escape`**:见下文。

### 6. `class` —— 字符类

```
class ::= '[' '^'? item+ ']'
```

- `[abc]` 匹配 a、b、c 中任意一个
- `[^abc]` 中开头的 `^` 表示**取反**,匹配除此之外的字符
- `item+` 要求至少一个元素,所以 `[]` 不合法

注意,`^` 只有紧跟 `[` 时才表示取反,在 `atom` 中它表示行首,同一个字符在不同上下文中含义不同。

### 7. `escape` —— 转义序列

```
escape ::= '\d' | '\w' | '\s' | '\D' | '\W' | '\S'
         | '\b' | '\B' | '\1'..'\9' | '\' char
```

| 转义 | 含义 |
|---|---|
| `\d` / `\D` | 数字 / 非数字 |
| `\w` / `\W` | 单词字符 `[A-Za-z0-9_]` / 非单词字符 |
| `\s` / `\S` | 空白 / 非空白 |
| `\b` / `\B` | 单词边界 / 非单词边界(零宽) |
| `\1`..`\9` | **反向引用**:匹配第 N 个捕获组**实际匹配到的文本** |
| `\` char | 转义任意字符为字面量,如 `\.`、`\*`、`\(` |

规律:小写与大写互为补集。反向引用的例子:`(\w)\1` 匹配 "aa"、"bb" 这样的重复字符。

## 四、完整解析示例

以 `(?:ab|c)+d?` 为例,它的语法树如下:

```
alt
└─ concat
   ├─ repeat
   │  ├─ atom: (?: alt )
   │  │        └─ alt
   │  │           ├─ concat
   │  │           │  ├─ repeat → atom 'a'
   │  │           │  └─ repeat → atom 'b'
   │  │           └─ concat
   │  │              └─ repeat → atom 'c'
   │  └─ quant: '+'
   └─ repeat
      ├─ atom 'd'
      └─ quant: '?'
```

## 五、文法中未定义或需注意的地方

这份文法是一个**简化版**,有几处留白或隐含约定:

1. **未定义的非终结符**:`literal`、`item`、`m`、`n`、`char` 都没有给出定义。通常的理解是:
   - `literal`:除元字符 `| * + ? ( ) [ ] { } . ^ $ \` 以外的任意字符
   - `item`:单个字符、范围 `a-z`、或 `\d` 之类的转义
   - `m`、`n`:十进制非负整数

2. **前缀冲突**:`'('`、`'(?:'`、`'(?='`、`'(?<='` 等有公共前缀,解析器需要向前多看几个字符(**最长匹配**)才能决定走哪个分支。

3. **反向引用只支持 1 到 9**:`\10` 会被解析成 `\1` 后跟字面量 `0`。

4. **`{` 的歧义**:实际引擎中 `a{x}` 这种不构成合法量词的写法,常被当作字面字符处理,而本文法未涵盖这种情况。

5. **无主量词**:按文法,`*abc` 开头的 `*` 不是任何 atom,因此是语法错误,这符合大多数引擎的行为。

6. **语义约束不在文法中**:例如 `{5,2}`(m > n)、后行断言内不允许变长模式(部分引擎的限制)、`\3` 引用不存在的组等问题,都需要在解析后另行检查。

## 六、对应的递归下降解析器骨架

这份文法几乎可以直接逐条翻译成代码,每条规则对应一个函数:

```python
def parse_alt():
    branches = [parse_concat()]
    while peek() == '|':
        advance()
        branches.append(parse_concat())
    return Alt(branches)

def parse_concat():
    items = []
    while peek() not in ('|', ')', EOF):   # concat 可为空
        items.append(parse_repeat())
    return Concat(items)

def parse_repeat():
    node = parse_atom()
    while peek() in ('*', '+', '?', '{'):
        node = parse_quant(node)
    return node

def parse_atom():
    if match('(?:'):  return group(parse_alt(), capture=False)
    if match('(?>'):  return atomic(parse_alt())
    if match('(?<='): return lookbehind(parse_alt(), neg=False)
    if match('(?<!'): return lookbehind(parse_alt(), neg=True)
    if match('(?='):  return lookahead(parse_alt(), neg=False)
    if match('(?!'):  return lookahead(parse_alt(), neg=True)
    if match('('):    return group(parse_alt(), capture=True)
    if peek() == '[': return parse_class()
    if peek() == '\\': return parse_escape()
    ...  # '.', '^', '$', literal
```

注意 `parse_atom` 中**较长的前缀要先判断**,比如 `(?<=` 必须在 `(` 之前检查,这正是第五节第 2 点所说的前缀冲突问题。

---

## 总结

这份文法用 7 条规则描述了现代正则表达式(接近 Perl/PCRE 风格)的核心语法:

- **四层结构** `alt → concat → repeat → atom` 决定了运算优先级:选择 < 连接 < 量词 < 原子;
- **`atom` 中的 `'(' alt ')'`** 实现了递归嵌套;
- **量词后缀**区分了贪婪、惰性、占有三种匹配策略;
- **环视和原子组**等高级特性也被纳入其中。

理解了这份文法,也就理解了正则引擎"读懂"一个正则表达式的过程。

# Expression optimization

## Available expression analysis(可用表达式分析)

### 一句话定义

可用表达式分析是编译器中一种经典的**数据流分析（Data Flow Analysis）**，用于判断在程序某一点，某个表达式的值是否**已经被计算过且未失效**，从而避免重复计算。它是**公共子表达式消除（CSE）**优化的理论基础。

## 一、核心概念

### 什么是"可用"？

一个表达式 `x op y` 在程序某点 **p** 处是 **available（可用）** 的，当且仅当：

```
从程序入口到达 p 的【每一条路径】上：
  1. 该表达式 x op y 都被计算过；
  2. 且计算之后，x 和 y 都没有被重新赋值（表达式未失效）。
```

**通俗理解**：如果表达式 `a + b` 在某点是可用的，说明它的值早就算好了、还存在**寄存器**/变量里，此处**不需要再算一遍**，直接复用即可。

### 为什么重要？

```
b = a + 1
c = a + 1     ← "a + 1" 是可用表达式，可直接复用 b 的结果
              → 优化为 c = b
```

这就是 **公共子表达式消除（Common Subexpression Elimination, CSE）**。



### 关键定义

对每个基本块（Basic Block）B，定义 4 个集合：

| 集合          | 含义                                         |
| ----------- | ------------------------------------------ |
| **GEN[B]**  | 块 B 内**生成**的可用表达式（在 B 内计算，且之后 B 内其操作数未被修改） |
| **KILL[B]** | 块 B 内被**杀死**的表达式（因某操作数在 B 内被重新赋值而失效）       |
| **IN[B]**   | 进入块 B 时可用的表达式集合                            |
| **OUT[B]**  | 离开块 B 时可用的表达式集合                            |

#### GEN 与 KILL 举例

```
基本块 B:
    t1 = a + b     ← 生成 "a+b"
    a  = c + d     ← a 被重新赋值 → 杀死所有含 a 的表达式（如 "a+b"）
    t2 = a + b     ← 重新生成 "a+b"（此时 a 是新值）

GEN[B]  = { a+b }   （最后仍然有效的）
KILL[B] = { 所有其他块中含 a 的表达式 }
```



### 数据流方程

可用表达式是典型的**前向（Forward）+ 必经（All-paths / 交集）**分析：

```
IN[B]  = ⋂  OUT[P]      （P 是 B 的所有前驱）
        P∈pred(B)

OUT[B] = GEN[B] ∪ (IN[B] − KILL[B])
```

### 两个关键特征

| 特征       | 可用表达式           | 原因               |
| -------- | --------------- | ---------------- |
| **方向**   | **前向（Forward）** | 从入口向出口传播         |
| **汇合运算** | **交集（∩）**       | 必须"每条路径"都可用，才算可用 |

> ⚠️ **注意汇合运算是交集 ∩**，这与"到达定值"（用并集 ∪）不同，是常见易混点。

## 四、求解算法（迭代法）

采用**不动点迭代（Iterative Fixed-Point Algorithm）**：

```
// 初始化
OUT[entry] = ∅              // 入口块无可用表达式
for each block B (except entry):
    OUT[B] = U              // 初始化为全集（Universal set）

// 迭代直到收敛
while (发生变化):
    for each block B (except entry):
        IN[B]  = ⋂ OUT[P]   for all predecessors P
        OUT[B] = GEN[B] ∪ (IN[B] − KILL[B])
```

### ⚠️ 关键初始化技巧

```
非入口块的 OUT 必须初始化为【全集 U】，而不是空集！
```

**原因**：因为汇合运算是**交集**。若初始化为空集，交集永远为空，算法会得到过于保守的错误结果。初始化为全集，才能让迭代逐步"收窄"到正确的不动点。

> 这是"交集类"数据流分析的通用规律：**交集用全集初始化，并集用空集初始化**。

## 五、完整示例

考虑如下控制流图（CFG）：

```
        ┌─────────────┐
        │ B1:         │
        │  t1 = a + b │   GEN = {a+b}
        │  t2 = a * c │   GEN = {a+b, a*c}
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │ B2:         │
        │  a = a + 1  │   KILL = {a+b, a*c}  (a 被改)
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │ B3:         │
        │  t3 = a + b │   GEN = {a+b}
        └─────────────┘
```

**分析过程**：

| 块   | GEN         | KILL        | IN          | OUT             |
| --- | ----------- | ----------- | ----------- | --------------- |
| B1  | {a+b, a\*c} | ∅           | ∅           | **{a+b, a\*c}** |
| B2  | ∅           | {a+b, a\*c} | {a+b, a\*c} | **∅**           |
| B3  | {a+b}       | ∅           | ∅           | **{a+b}**       |

**结论**：

- 进入 B3 时 `IN[B3] = ∅`，说明 `a+b` 在 B3 入口**不可用**（因为 B2 修改了 a）。
- 所以 B3 中的 `t3 = a + b` **不能**复用 B1 的 `t1`——必须重新计算。✅ 分析正确。

## 六、应用：公共子表达式消除

有了可用表达式信息，编译器可以这样优化：

```
优化前：                    优化后：
────────────              ────────────
t1 = a + b                t1 = a + b
...（a、b 未被修改）        ...
t2 = a + b        →       t2 = t1      ← 复用！省一次加法
```

**判断条件**：当遇到表达式 `a + b`，若它在**当前点是可用的**（∈ IN），则可用之前保存的结果替换，避免重复计算。

## 七、与其他数据流分析的对比

| 分析类型                           | 方向     | 汇合运算     | 初始化  | 用途                  |
| ------------------------------ | ------ | -------- | ---- | ------------------- |
| **可用表达式**                      | 前向     | **交集 ∩** | 全集 U | 公共子表达式消除（CSE）       |
| **到达定值**（Reaching Def）         | 前向     | 并集 ∪     | 空集 ∅ | 常量传播、use-def 链      |
| **活跃变量**（Live Variable）        | **后向** | 并集 ∪     | 空集 ∅ | 寄存器分配、死代码消除         |
| **忙碌表达式**（Busy/Very Busy Expr） | 后向     | 交集 ∩     | 全集 U | 代码提升（Code Hoisting） |

> 这张表是数据流分析的"四象限"，**面试高频考点**，建议熟记方向与汇合运算的组合。

## 八、面试要点

如果你面试 AI 编译器 / 编译器岗位，关于可用表达式可能被问到：

| 问题                        | 要点                                                             |
| ------------------------- | -------------------------------------------------------------- |
| **可用表达式是前向还是后向？汇合运算是什么？** | 前向 + 交集                                                        |
| **为什么初始化用全集而不是空集？**       | 交集运算，空集会导致结果恒为空、过度保守                                           |
| **它支持哪种优化？**              | 公共子表达式消除（CSE）                                                  |
| **和到达定值的区别？**             | 都是前向，但可用表达式用交集（必经路径），到达定值用并集（存在路径）                             |
| **算法一定会收敛吗？**             | 会。集合有限 + 转移函数单调 → 有限步内到达不动点                                    |
| **在 SSA / LLVM 中如何体现？**   | LLVM 有 GVN（Global Value Numbering）等更强的等价实现；MLIR 中也有相应 CSE Pass |

### 与现代编译器的联系

```
经典理论（可用表达式 + CSE）
      ↓ 演进
现代实现：
  - LLVM 的 EarlyCSE / GVN Pass
  - GVN（全局值编号）比经典可用表达式更强大
  - MLIR 的 -cse Pass
```

> **建议**：理解经典理论后，去读 LLVM 的 `EarlyCSE.cpp` 或 `-cse` Pass 源码，把"理论"和"工业实现"打通，这正是 AI 编译器岗位看重的深度。

---

> 📌 **总结**：可用表达式分析 = **前向 + 交集 + 全集初始化**的数据流分析，核心用途是**消除重复计算（CSE）**。它是编译器优化的经典基石，理解它有助于掌握整个数据流分析框架，也是编译器岗面试的必考知识点。
